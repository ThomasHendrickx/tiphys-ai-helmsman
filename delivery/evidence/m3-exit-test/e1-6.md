## Why `red-witness` is red, and why no version of this change makes it green

**The mechanism, not the instance.** A witness spec's `mutation.find` is a
verbatim quotation of a source line, which makes that line a coupling point
owned by no phase. Two M3-P8 specs quote the `full:` profile-promotion line of
`src/commands/doctor.ts`, and the exit test's DESIGNATED subject requires adding
a condition to exactly that line.

Both arms were measured on this head, with everything else green:

| arm | what was done | result |
|---|---|---|
| A | repair both specs so their promotion member matches the new source text | `rule (d): declared dangerous state does not intersect the phase diff (member 0 ...)` for both |
| B | leave both specs exactly as `main` has them | `error: mutation find text "  full: [\"gh-missing\", \"remote-missing\", \"retention-undeclared\"]," does not occur in src/commands/doctor.ts` for both |

Editing a spec file puts it in the phase diff, which makes it one of the phase's
OWN witnesses, and rule (d) at src/witness/run.ts:1251 then requires EVERY member
of it to intersect the diff. Those specs' other members mutate the RETENTION
code, which this change does not touch. Leaving them alone leaves a find text
that no longer occurs. Arm A is what the branch carries.

Three things were deliberately NOT done, each of which would have turned the
gate green while making the artifact worse: reformatting the retention code so
those members intersect; removing the promotion member from the M3-P8 specs;
dropping the profile promotion from the subject change, which would silently
change what the exit test measured.

**This is a finding about the shipped harness, and it is exactly the kind of
thing the exit test exists to surface.** It is handed to the orchestrator rather
than ruled on here.
