checklist hazard-review
probes 9
1. hazard-classes-addressed [hazard-classes] evidence-required
   Walk the phase's declared `hazard-classes[]` one at a time and produce one statement per class: either a finding it caused, or what you probed and why the class is cleared. Not one statement for the set. This is the completeness rule the verdict schema's `hazard-classes-addressed[]` carries and `verdict-hazard-classes-addressed` compares against the plan phase, so a class you silently skip is a red gate rather than an omission nobody notices.
2. hazard-what-can-block [hazard-family] evidence-required
   What in this change can BLOCK forever? Build the blocking state and run the code at it: `mkfifo` a path the change opens for reading, point it at a file on a filesystem that does not answer, hand it a descriptor nothing writes to. A read of a path whose type has not been established is the mechanism; name every call site of it, not the one instance you found. Paste the construction and what the program did.
3. hazard-what-can-be-lost [hazard-family] evidence-required
   What can be LOST? Kill the process mid-write, with SIGKILL rather than a handler-friendly signal, at the moment the change is rewriting a file, renaming one, or holding data only in memory. Then read what is on disk. Name the window between the last durable state and the next one, and say what a reader finds inside it.
4. hazard-what-can-never-exit [hazard-family] evidence-required
   What can NEVER EXIT? Force the contention rather than reasoning about it: run two writers against one lease, two clones against one ref, two acquirers against one lock, and let them race for real. A concurrency path where no contention can occur is green, registered and worthless. Record the observed stderr from the real collision rather than a hand-written example of it, because a retry signature derived from an imagined message matches nothing.
5. hazard-what-can-destroy [hazard-family] evidence-required
   What can DESTROY work? Run the destructive path against a branch carrying COMMITTED UNPUSHED WORK, not against an empty branch, and see whether that work survives. A destroy exercised on a branch carrying nothing is the red-witness rule's own counter-example: it passes, it is registered, and it guards nothing. Then say whether the command's own contract declares that authority, or inherits force semantics from a caller.
6. c2-liveness-vocabulary [declared-process-document] evidence-required
   Does any stage, clause or duty in the artifact define COMPLETION in terms of a process being alive, in any wording? Constraint C-2 forbids pid, process liveness, signals and /proc for identity or exclusion; liveness is lease freshness. The grep for those four tokens finds the spellings someone thought of, and this probe is for the ones nobody did. The contrast to look for: "the stage completes when the agent finishes" against "the stage completes when the lease is renewed past T". Quote every clause you judged and say which side of that line it falls on. Covers `assurance-modes.yaml`, `AGENTS.md` and every file under `roles/`.
7. clause-text-matches-row [declared-process-document] evidence-required
   For each clause id the clause map resolves, does the TEXT under that heading discharge the requirement row it is mapped to, or say something weaker? The clause map proves PRESENCE and never content: it checks that the id occurs in the named artifact, so a heading with a sentiment under it passes exactly as a heading with a rule under it does. Quote the clause text and the row side by side for every mapped clause in the diff, and name any pair where the clause is the softer of the two.
8. honest-failure-substance [honesty-contract] evidence-required
   Does each `honest-failures[]` entry's `cause`, `exposure-window` and `structural-fix` say something a READER COULD ACT ON? The schema makes those fields non-empty and non-whitespace and can do no more, so an entry reading "cause: a bug; exposure-window: some time; structural-fix: fixed it" is structurally complete and semantically empty. Quote each field and say what a reader could do with it.
9. contract-avoidance [honesty-contract] evidence-required
   Did any record in this phase route AROUND a required field rather than filling it? The three shapes seen here: a `claims[]` section left empty while the prose makes an impossibility claim; a `fix-round` block absent from a round that demonstrably happened; a deviation described in a narrative paragraph rather than declared in `deviations[]`. This is the probe for the hazard nobody can fixture, that a schema can make an honest record MORE EXPENSIVE to write than a dishonest one, because that is a property of the ratio between two authoring costs and no single instance exhibits it. Read the prose against the structure and name every place they disagree.
