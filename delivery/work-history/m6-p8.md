## What changed, one line per file

- `.github/workflows/gates.yml`: the separate `npm test` step is gone (the
  `suite` gate runs it); the M1 exit test step has
  `if: github.event_name != 'pull_request'`.
- `gate-registry.yaml`: `red-witness` gets `events: [pull_request, push]` and
  `parameters: [base, head, event]`.
- `src/gates/red-witness.ts`: `--event`; `storedWitnessEvaluated` selects on
  `pull_request` only (mutated file or a test file it runs changed, a moved or
  renamed-inside test file included); push and no event evaluate every stored
  witness; a failed diff is `error` before any selection; the detail line
  counts skipped stored witnesses; `witness-records.json` lists their ids.
- `src/gates/manifest.ts`: `RunParameter` gains `event`; `OPTIONAL_PARAMETERS`
  (`event` only): a run naming no `--event` hands the gate nothing, not an
  error.
- `src/gates/run.ts`: passes a declared parameter only when the run supplied
  it; the missing-parameter error skips `OPTIONAL_PARAMETERS`.
- `src/gates/schemas/gate-manifest.schema.json`: `event` in the parameters
  enum.
- `schemas/gate-registry.schema.json`: `event` in the parameters enum.
  OUTSIDE the plan's files-to-touch list. Needed because the only other
  channel, an environment variable, is red under the existing test "no
  environment variable changes a production gate's reported status (grep over
  the gate sources)" (test/gate-registry.test.ts).
- `test/witness.test.ts`: the five p8-selection tests; the existing test
  "reverting the change that broke a stored witness returns exit zero" now
  passes `event: "pull_request"` (it pinned `units 1`, which is the pull-request
  selection; with no event both stored witnesses are evaluated).
- `test/gate-registry.test.ts`: the p8-workflow test.
- `test/gate-event-parameter.test.ts`: the runner hands `--event` to a gate
  declaring it.
- `test/behaviors.json`: seven rows.
- `witness/m6-p8-pull-request-selection.json`,
  `witness/m6-p8-runner-hands-event.json`, and the capture
  `witness/captures/m6-p8-git-diff-test-file-move.txt` (rule (f): the gate file
  matches the spawn grep).

No other test pinned the old workflow shape or the red-witness detail wording.
`test/fixtures/red-witness-evidence.txt` quotes the old wording as a captured
historical run and is left as it is.
