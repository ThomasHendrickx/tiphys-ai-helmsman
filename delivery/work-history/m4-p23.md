the recorded output is evidence on the red arm as well as the green one.

## What this phase did NOT cover

1. **The verification is per DESTINATION CLAUSE, not per rule.** Where several
   rows share a kernel clause they share its probe, so the row-level claim is
   "this rule's destination is that clause" and the command-level claim is "that
   clause exists and carries the named obligation". 280 rows map to 119
   disposition groups.
2. **"Not weaker" is mechanical in FORM and still a reading in SUBSTANCE.** The
   witness pair proves the probe resolves in the destination and does not
   resolve in a same-kind sibling. It does not prove the destination's clause is
   as strong as the retired rule. The claim-grep row is the exception where the
   mechanical form reaches the substance, because roles/implementer.md:295
   carries the grep PATTERN literally; most rows are not that lucky. This is the
   thing a reviewer should spot-check, and it is named here rather than left to
   be discovered.
3. **The negative witnesses are all `sibling` kind, none `history`.** A witness
   that runs the probe against a pre-port git blob would be literally "red under
   the old rule". I chose sibling because a history witness needs full history
   and fails in a shallow clone, which would make the checker's verdict depend
   on how the repository was fetched. The checker accepts both kinds, so a later
   phase can strengthen individual rows without changing the guard.
4. **The checker does not compare captured OUTPUT, only exit codes.** Byte
   comparison would redden every time a file grew a line, which would train a
   reader to regenerate captures without reading them. The output is recorded
   for a human; the exit code is what is enforced.
5. **Two of the four FALSE rows are recorded and not edited**, because their
   text is in the skills tree and this phase's files-to-touch list does not
   include it.
6. **Nothing in the three roots is deleted** (criterion 7). It needs no separate
   mechanism: a deletion removes an anchor and the surviving row goes red as
   stale, which is what the rule-without-a-row and stale-row tests assert.
7. **The rows were assigned by reading**, in groups, first by section span and
   then pinned by RULE ID. The switch was forced by a bug of my own: correcting
   `CLAUDE.md` shifted every line after the edit, the span table shifted with it
   by hand, and sixteen rows silently took their NEIGHBOUR's disposition. It was
   caught by diffing the regenerated rows against the previous ones rather than
   by the checker, which was green throughout because every row still had a
   well-formed group. Ids are content-derived and immune to line motion, so the
   committed mapping is now by id. The JUDGMENT that a given rule belongs to a
   given kernel clause is still mine and is the reviewable part.
8. **The green checker never reddened on that bug, and it never would have.**
   A misassigned row is a row pointing at the wrong destination with a probe
   that still resolves there. Nothing mechanical distinguishes it from a correct
   row. That is the honest limit of this guard: it enforces that every rule has
   a resolved disposition, not that the disposition is the right one.

## An environment warning I created rather than inherited

I stopped a long-running suite with `pkill -f "node --test test/**"`. **That
pattern is broader than it looks and this container runs several agents at
once.** `pkill -f` takes a REGEX, so `test/**` is "test/" followed by any number
of asterisks, which matches EVERY `node --test test/...` process on the machine,
including other agents' worktrees. A `node --test test/cutover-entry.test.ts`
belonging to another unit was visible in `ps` immediately afterwards; I cannot
tell from `ps` alone whether it survived my signal or was restarted after it,
and I am not claiming either.

The rule I should have followed, and the one to carry: **never kill by pattern
in a shared container.** Kill by the PID of the process you started, or let it
finish. This is the same shape as the watchdog rules one level down: a selector
that matches more than its author intends is indistinguishable from a correct
one until it hits something.
