- `credential-token` vs `credential-scrub`: the token gate's failure is an
  implementer holding a pull-request-capable credential. `credential-scrub`
  builds the executor's child environment with the executor's own
  `buildChildEnv` and probes every source such a credential could resolve from
  (src/gates/credentials.ts:19 onward), so the failure is covered where it
  matters: in the child. The token gate never asserted anything (not-applicable
  without the token, error with it).

  the enforcing review gate; tests that drive the script through the runner now

  load `src/gates/schemas/*.schema.json` through the closed keyword set. Each
  document is loaded by its consumer at run time (`loadSchema` refuses an
  unimplemented keyword), so a bad document reddens the tests of its consumer,
  but no single test enumerates the directory. Recorded as an open point, not
  closed here: see "Open questions".

  cheap: `--result`/`--evidence` arm in the script, 70 lines, the bare mode
