### 1.4 HALT CHECK (a): does M2's validator as delivered emit
`INVALID <json-pointer> <message>` with deterministic ordering?

**TRUE.** Two sites, both read from the delivered source.

`src/gates/validate.ts` line 90 (the string is the module's public contract):

```
$ grep -n 'return `INVALID' src/gates/validate.ts
90:  return `INVALID ${diagnostic.pointer} ${diagnostic.message}`;
```

The ordering is a FINAL SORT applied to the collected list, so it is a
property of the contract and not of the traversal. `src/gates/validate.ts`,
`validate()`:

```
  collected.sort((a, b) => {
    if (a.pointer !== b.pointer) {
      return a.pointer < b.pointer ? -1 : 1;
    }
    if (a.message === b.message) {
      return 0;
    }
    return a.message < b.message ? -1 : 1;
  });
```

The module header states the same rule in terms and states WHY it is a final
sort: "The final sort is what makes the order a property of the CONTRACT
rather than of the traversal, so an engine that walks differently still emits
the same lines in the same order." That sentence is the one that makes DR-0013
clause 6 mechanically keepable, and it is in the delivered artifact.
