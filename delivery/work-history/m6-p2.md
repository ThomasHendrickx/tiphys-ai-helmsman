## Step 1: the classifier and the merge gate by tier (commit 7df8d05)

- `src/gates/merge-preconditions.ts`: `REVIEW_BUDGET_ROWS`, `tierOfPath`,
  `TIER_RANK` and the `none` tier removed. New, all pure: `readRuntimeSet`
  (charter text to declared | undeclared | invalid), `manifestDifferences`
  (two parsed manifests to version-field changes and other changes),
  `classifyTier` (declaration + changed paths + both sides of the paths a rule
  reads to a tier and one reason per path). `classifyReviewBudget` keeps the
  diff mechanics (`git rev-parse --show-prefix`, `git diff -z --no-renames
  --name-only base...head`, outside-the-prefix is pair, every git failure an
  error) and adds `git merge-base base head`, then reads `charter.yaml` at the
  MERGE BASE and both sides of the charter and of each declared manifest through
  `git ls-tree -z` (presence) plus `git cat-file blob` (bytes). A non-regular
  blob (symlink, tree, submodule) or a failed read is `pair`.
- Rule order in `classifyTier`, a refinement of the brief stated plainly: a
  declared MANIFEST is judged before the declared PATHS. Without that,
  `plugin/package.json` under the declared `plugin/` prefix is judged `pair`
  and the #224 bump (criterion p2-version-bump) is not `single`. Measured:
  witness m6-p2-version-bump-single member m2 moves the manifest rule behind
  the prefixes and the p2-version-bump test fails with `plugin/package.json`
  `pair` (step 7).
- A version field counts only when both sides are version strings
  (`^`/`~` allowed on a pin): a pin rewritten to `file:...` or to an object
  changes what is installed and is `pair`. Stricter than the brief's wording.
- `REQUIRED_VERDICTS` is `{pair: 2, single: 1}`. merge-preconditions no longer
  returns not-applicable for a below-pair change: it reads the corpus for both
  tiers; the selection row is red below the tier's count. `pair`: condition-1
