## Step 1: the classifier and the merge gate by tier (commit 7df8d05)

- `src/gates/merge-preconditions.ts`: `REVIEW_BUDGET_ROWS`, `tierOfPath`,
  `TIER_RANK` and the `none` tier removed. New, all pure: `readRuntimeSet`
  (charter text to declared | undeclared | invalid), `manifestDifferences`
  (two parsed manifests to version-field changes and other changes),
  `classifyTier` (declaration + changed paths + both sides of the paths a rule
  reads to a tier and one reason per path). `classifyReviewBudget` keeps the
  diff mechanics (`git rev-parse --show-prefix`, `git diff -z --no-renames
  --name-only base...head`, outside-the-prefix is pair, every git failure an
  error) and adds `git merge-base base head`, then reads `charter.yaml` at the
  MERGE BASE and both sides of the charter and of each declared manifest through
  `git ls-tree -z` (presence) plus `git cat-file blob` (bytes). A non-regular
  blob (symlink, tree, submodule) or a failed read is `pair`.
- Rule order in `classifyTier`, a refinement of the brief stated plainly: a
  declared MANIFEST is judged before the declared PATHS. Without that,
  `plugin/package.json` under the declared `plugin/` prefix is always `pair`
  and the #224 bump (criterion p2-version-bump) cannot be `single`.
- A version field counts only when both sides are version strings
  (`^`/`~` allowed on a pin): a pin rewritten to `file:...` or to an object
  changes what is installed and is `pair`. Stricter than the brief's wording.
- `REQUIRED_VERDICTS` is `{pair: 2, single: 1}`. merge-preconditions no longer
  returns not-applicable for a below-pair change: it reads the corpus for both
  tiers; the selection row is red below the tier's count. `pair`: condition-1
  (decorrelation, produced-by only) and condition-2 (pair approves), and
  condition-6 (arbitration). `single`: one row, condition-2 `judgeSingleApproves`
  (every admitted verdict reads exactly APPROVE; severities reported, not gated,
  per DR-0063's "a finding blocks only if it makes a shipped artefact wrong").
  No decorrelation row and no arbitration row. Condition 3 and
  `judgeCriteriaWalked` removed. Without `--base` the tier is `pair` (fail
  closed). Sentences and detail say `DR-0063 <tier>`.
- `scripts/check-dual-review.mjs`: `REQUIRED_VERDICTS` there is now
  `REQUIRED_BY_TIER.pair` (so the witnessed line
  `if (found.admittedCount < REQUIRED_VERDICTS) {` is byte-identical); a
  `single` change is not-applicable with precondition
  `review-budget-requires-pair-review` (renamed from
  `review-budget-requires-dual-review`).
- `src/checks.ts`: `DECORRELATION_DIMENSIONS = ["produced-by"]`; with
  produced-by exempt by the single-family declaration the REPORT line says the
  reviews were counted and compared on no dimension; `verdict-hazard-classes-
  addressed` now exempts only `review-contract: criteria` (history), so a new
  verdict with no `review-contract` is held to it.
- `src/gates/suite.ts`: the merge-base behavior-deletion finding removed; the
  base registry is still read for the counts document. Every head behavior must
  still resolve.
- `src/roles.ts`: `REVIEW_CONTRACTS = ["hazard"]`, `DROPPED_REVIEW_CONTRACT`;
  `src/commands/brief.ts` defaults to `hazard` and refuses `criteria` naming
