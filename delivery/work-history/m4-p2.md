### Step 5: the completion precondition

src/spawn.ts:299 is a new `turnEndEvidence(fleet, taskId)` and src/spawn.ts:629
is its call, placed AFTER the `incomplete` arm and BEFORE the scrub-root
removal. It reads `turnEndPath(fleet, taskId)` (src/task.ts:254) through

FIFO at the turn-end path is a reported refusal and not a blocked open: that is
the CR-520 hazard from meta.json, one path along.

It produces FOUR distinct refusals rather than one, and the distinction is the
point of criterion 3: absent, unreadable, unparseable, and
parseable-but-wrongly-shaped. A check written as `existsSync` is green on the
last THREE, not two: `existsSync` returns true for a FIFO as readily as for a
corrupt file, so the naive check passes every case except the absence it was
written for. That is a guard whose condition does not test the property that
matters. Member 1 of the first witness spec is exactly that weakening, and it
reddens. The test covers two of those three (unparseable, wrongly-shaped); the
FIFO arm is reached through `readRegularFileIfPresent` and is NOT separately
tested here, which is recorded rather than implied.

A refusal here rolls nothing back and removes nothing, and its reason
enumerates the residue and names the route out, in the same shape the
`incomplete` arm and the raised-adapter arm already use.

**The enumeration is conditional, and that took a second pass to get right.**
The first version named the scrub root unconditionally. Under
`--allow-pr-credentials` (SpawnOptions' declared escape hatch) `childEnv` is
undefined and NO scrub root is ever staged, so that message would have
enumerated a directory that does not exist, in the one sentence an operator
uses to find the residue after a refusal. src/spawn.ts:636 now branches on
`childEnv === undefined`. This arm has NO test: the escape hatch is exercised
elsewhere (`spawn-allow-pr-credentials-passthrough`) but not in composition
with a fabricated completion, and I am recording that rather than implying the
branch is covered.
