## Design, decided before code

Three measured facts shaped it.

1. `check-dual-review` is NOT in gates.manifest.json, so the runner never
   executes it in CI; CI runs it only through a legacy workflow step that
   passes no `--base` (the step is not on this phase's declaration).
   `merge-preconditions` IS in the manifest, and the harness row for it in
   scripts/m2-exit-test.sh:226 is `green|not-applicable`, so a red from it
   fails the pull-request bundle. It is therefore the gate that can make a
   shipped-code pull request fail in CI.
2. Both gates' precondition today is `check-dual-review --precondition .`,
   which exits 1 when no verdict document exists, so on a branch with no
   verdict the runner reports not-applicable WITHOUT spawning either gate.
   That precondition is the review-gate-never-runs mechanism, and it is the
   thing that has to change.
3. Adding `check-dual-review` to the manifest is refused by the harness: a
   manifest gate with no row in scripts/m2-exit-test.sh is asserted
   required-green, so every paperwork-only pull request would fail.
