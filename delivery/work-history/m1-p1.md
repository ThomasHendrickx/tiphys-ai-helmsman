## Key decisions and the why that is invisible in the diff

1. typescript pinned to 7.0.2: the current latest dist-tag on the npm registry at implementation time (2026-08-04), the stable native-compiler line. Verified empirically before pinning that it supports the plan's exact mechanism: tsc -b over a composite src project plus a noEmit test project with a project reference, and all mandated flags (strict, NodeNext, erasableSyntaxOnly, rewriteRelativeImportExtensions, verbatimModuleSyntax). The fallback considered was 6.0.3 (last TS6 stable); not needed. The lockfile carries the platform-specific @typescript/typescript-* optional packages; npm ci on the linux-x64 CI runner installs the right one.
2. @types/node 26.1.2 added as a second devDependency, pinned exact, matching the decided Node 26 floor. The plan's step 2 names only typescript; without @types/node the mandated strict build cannot pass at all (tsc emits TS2591 "Cannot find name 'process'" for every Node builtin reference). Declared as a deviation below, not a silent extra.
3. "types": ["node"] added to both tsconfigs: under typescript 7.0.2 the implicit @types auto-inclusion did not resolve @types/node (build failed with TS2591 until the explicit entry was added; the compiler's own error message prescribes exactly this). This is an addition to the plan's enumerated flag list, same rationale as item 2.
4. target es2024 chosen as the "target compatible with Node 26" the plan asks for: fully supported by Node 26 (and by the local Node 22 used for execution), no downleveling of the syntax in use.
5. src/version.ts locates package.json by walking up from the running module's directory instead of a fixed relative path: the same source runs at different depths (src/ under type stripping, dist/src/ compiled, and node_modules/@tiphys/kernel/dist/src/ when installed), so any fixed depth would break one of criterion 3, gate 3, or criterion 11.
6. Missing subcommand (bare "tiphys") is treated as unknown: usage to stderr, exit 64. The plan specifies only "any unknown subcommand"; the same code path was the smallest consistent reading.
7. gates.yml fan-in uses if: always() plus an explicit needs.test.result check: without always(), a failed matrix leg leaves the gates job skipped, and a skipped check can satisfy branch protection; the explicit check makes gates red whenever any leg is not success (PR-002's intent).
8. The workflow's push trigger names main explicitly. Note recorded for the orchestrator: the GitHub repository's default-branch setting currently points at the orchestration session branch (claude/tiphys-kernel-orchestration-2n5m7s); DR-0004 owner action item 1 confirms main as the default, and the plan's merge target for every phase is main, so main is the correct trigger; the pull_request trigger covers the PR gates check regardless of the default-branch setting.
9. .gitignore adds *.tsbuildinfo and coverage/ beyond the plan's list: tsc -b writes tsconfig.test.tsbuildinfo at the repo root (the noEmit test project has no outDir), and criterion 2 requires a clean porcelain after build.
10. LICENSE is the canonical text downloaded from https://www.apache.org/licenses/LICENSE-2.0.txt (202 lines, pure ASCII), not retyped.
11. Commit messages carry no AI model or tool names, per the phase protocol.

## CI correctness argument (CI not executable from this environment)

gates.yml declares: name gates; triggers pull_request (all branches) and push to main; concurrency group gates-${{ github.ref }} with cancel-in-progress true (per-ref, cancels superseded runs); job test with strategy.matrix.node = [26] (exactly one version, DR-0002) on ubuntu-latest (DR-0003), steps actions/checkout@v4, actions/setup-node@v4 with node-version from the matrix, then npm ci, npm run build, npm test (the three gates in order; npm ci installs the pinned typescript from the committed lockfile); job gates, non-matrixed, needs: test, if: always(), single step that exits 1 unless needs.test.result == "success", so the check context named exactly "gates" (DR-0004's required context) is red when any leg fails, green only when all legs succeed, and never satisfied-by-skip. The workflow proves itself on the PR the orchestrator opens (criterion 7).
