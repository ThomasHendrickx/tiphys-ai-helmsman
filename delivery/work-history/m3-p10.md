### MECHANISM M3: the artifact is never executed before it is published

**The mechanism: every pre-publish check inspects a LISTING; nothing installs the
thing and runs it.** Kept separate from M2 because the fix is different. M2 is
"read instead of model"; M3 is "execute instead of inspect".

The reviewer's measurement: changing `files` from `dist` to `dist/bin`, one word,
produced a package whose bin dies with `ERR_MODULE_NOT_FOUND` and which passed
both pack tests, the workflow's own pack check and the licence gate. Only the
post-publish step caught it, which is after the irreversible action.

Two fixes, and the plan's own hazard row is why they are two:

1. **Release verification runs BEFORE the publish, on EVERY dispatch including a
   rehearsal.** The `--tarball` mode existed for exactly this and was simply not
   wired in. The post-publish run against the registry is kept as well, because
   it answers a different question: not "does this artifact work" but "does the
   artifact the registry now serves work".
2. **The `dist` leg got an oracle.** Every other shipped directory is compared
   against `git ls-files`; `dist/` is built and untracked so that cannot be its
   oracle, and it was getting a PRESENCE check, which is precisely the shape the
   plan's hazard row defeats. Its oracle is now the built tree itself: every file
   under `dist/` on disk must appear in the listing, name for name. That is in
   both the workflow's inline check and `test/license-gate.test.ts`.

HRB-10 is folded in here: the gate now prints the build state beside the pack
count, because `--ignore-scripts` suppresses `prepack` and the listing is
therefore a function of build state (181 entries built, 60 not).

Every step of the release workflow, in order, classified, at the reviewed head
and at this one. This is the derivation, because the finding is about ORDER and a
grep cannot see order.
