## Step 0: reading and design decisions

Read DR-0061 to DR-0064, the M6-P4 plan section, the brief, and the files the
brief names. Decisions taken before writing code:

- D1. The criterion mapping extends the `suite` gate with `--plan <file>` and
  `--phase <id>` (the brief's preferred shape), so the suite runs once and its
  own reporter stream is the input. No new gate is registered, so
  `gate-registry.yaml` is not edited (M6-P3 rewrites it in parallel).
- D2. The phase id is matched case-insensitively, because CI derives `--phase`
  from the branch in lower case (`m6-p4`) while plan ids are upper case
  (`M6-P4`). An exact match would make the criteria half silently
  not-applicable on every CI run.
- D3. `check.tests` titles are compared by exact string equality against
  reported TEST points (not suites, not the zero-test file phantom), and
  EVERY reported point with that title must pass. No prefix or substring match.
- D4. `check.command` is spawned with an argv and no shell. An argv whose
  program is a shell given `-c` (an inline script) is refused, because a shell
  script's exit is whatever its last command returns.
- D5. The schema keeps to the declared authoring vocabulary (src/validate.ts:144):
  "at least one of tests and command" is written with `oneOf`, not `anyOf`,
  so `src/validate.ts` is not touched.
- D6. The `$comment` diet waits for the M6-P3 merge: removing clause ids from
  `$comment` reddens `scripts/check-clause-map.mjs` on this base, and M6-P3
  deletes the clause map.

## Step 1: implementation (commits ce8e0ca, 4 files of src plus schemas)

- `schemas/plan.schema.json`: an acceptance item is `oneOf` `check` /
  `not-testable`; `$defs/criterionCheck` is `tests` (non-empty, unique exact
  titles) and/or `command` (non-empty argv). Ajv strict mode needs each `oneOf`
  branch to declare the property it requires, so each branch carries a
  `properties` entry. "At least one of tests and command" is branch 1
  `required: [tests]`, branch 2 `required: [command]` with `tests` typed `null`
  (a present tests array is typed array, so it is not null, and both-present
  matches branch 1 only; M2b below reddens when that null arm is removed).
- `src/criteria.ts` (new): reads a phase's criteria, finds a phase ignoring
  case (D2), validates a plan against the schema before reading it, judges
  `check.tests` against reported points (D3), runs `check.command` with argv,
  `shell: false`, cwd = project root, `--check-timeout` (default 600 s), and
  refuses `sh -c`-style argv unrun (D4); counts criteria per phase; renders the
  hazard brief's not-testable questions.
- `src/gates/suite.ts`: `--plan <file> --phase <id> [--check-timeout <s>]`,
  both-or-neither (64 otherwise). The plan is read and validated BEFORE the
  suite runs (error on an unreadable or invalid plan, error on two phases with
  one id). A plan without the phase makes only the criteria half
  not-applicable, and the detail says so. Criteria findings join the suite's
  findings (red), `counts.json` gains a `criteria` object, and the detail ends
  with `criteria of <phase> in <plan>: N criterion(s), P proven by their check,
  U unproven, T not-testable`. `pointOutcome` is now the one classification
  both `bucketPoints` and the criteria judge use.
- `src/commands/plan.ts`: `tiphys plan count --plan <file> [--phase-id <id>]`.
- `src/commands/brief.ts`: the clean-room-reviewer brief ends its phase
  section with "# Not-testable criteria: questions this review answers", also
  when empty.
- `schemas/final-report.schema.json` requires `not-testable`; `src/stamp.ts`
  gets a RULES_SINCE row so unstamped history keeps validating.
- `templates/plan.example.yaml` shows `check.command`, `check.tests` and
  `not-testable`; `templates/final-report.example.yaml` shows the count.
- Fixtures updated to the new shape: `test/fixtures/plan-no-fill-in.yaml`, the
  decoy criterion in test/checks.test.ts:343.

### Hazard self-review ("can this pass while the thing it guards is broken?")

1. Proven by a test that was skipped, a todo, filtered out, or never ran.
   Attacked with a fixture whose suite ALONE is green (the control run in the
   named test exits 0): skipped, todo, `--test-skip-pattern`-filtered and a
   typo'd title each redden only through the criteria judge (M3, M5, M6b).
   did-not-run (cancelledByParent) takes the same `pointOutcome` arm the suite
   counts with. What survives: a check can only be as strong as the test it
   names; a test that asserts nothing still passes. That is the plan
   reviewer's finding to raise (roles/adversarial-plan-reviewer.md), not a
   thing the kernel can see.
2. A title matching a different test. Titles are compared with `===` against
   TEST points only (suites and the zero-test file phantom excluded). Attacked
   with a prefix of a real title and a real title's extension (M4). Two tests
   sharing one title: every point must pass, so a passing twin cannot cover a
   failing one (M6a). What survives: a title that is exactly equal to a
   different test's title in another file is judged over both, which is the
   safe direction (red if either fails).
3. A command that cannot fail, or runs through a shell. The argv is spawned
   with `shell: false`; `false || true` is red (exit 1), and would be green
   under a shell (M7). `sh -c` style argv is refused unrun (M8); nonzero,
   signal, timeout and spawn failure each red with the exit and output tail
   (M9, M10). What survives, stated as open: a shell reached indirectly
   (`env sh -c ...`, `bash script.sh` whose script swallows failures,
   `npm run x` whose script is shell), and a program that exits 0 whatever
   happens (`node -e "...; process.exit(0)"`). I did not find a mechanical
   test for those; the plan-writer and plan-reviewer briefs name the shape.
4. `not-testable` as the easy default. The count is visible in four places,
   all computed from the plan: the suite gate detail (`T not-testable`),
   `tiphys plan count`, the final report's required per-phase list, and the
   hazard brief, which turns each one into a question the reviewer must
   answer. The plan-review brief makes a testable `not-testable` a finding.
   What survives: nothing caps the ratio; DR-0064 is an experiment to be read
   from the counts, so a cap would be a new rule nobody decided.
5. A `$comment` removal changing what a schema accepts: not reached in this
   step (the diet is deferred). Prepared: the diet script asserts
   parsed(after) == parsed(before) with every `$comment` key removed, for every
   file, before writing it.
