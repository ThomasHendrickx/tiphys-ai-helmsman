## Step 1: M2-C-1 verification (before any code)

Plan section 1.1 names the delivered M1 contract this phase consumes:
`classifyEntry` and `refuseOpenForWrite` in `src/task.ts` (M1-P5, merged at
58ac964, now part of `origin/main`'s history). Read `src/task.ts` in full
(lines 1-466).

Verified, matching the plan's assumption exactly:

- `classifyEntry(path): EntryClass` at `src/task.ts:118-149`. lstat then
  stat, `{ kind: "regular" }` only for a real file; `irregular` names the
  observed type in `reason` (`describeType`, lines 93-110, covers directory,
  FIFO, socket, character device, block device); `unexaminable` when lstat or
  stat itself throws something other than ENOENT; `absent` / `dangling` for
  nothing there / a dangling symlink.
- `refuseOpenForWrite(path): string | undefined` at `src/task.ts:158-164`:
  refuses irregular and unexaminable, permits absent (creation is the point).
- `readRegularFileIfPresent(path): RegularRead` at `src/task.ts:179-201`:
  probes via `classifyEntry` before ever calling `readFileSync`, returns
  `{kind:"refused", reason}` naming the path and type for anything not a
  regular file (or unreadable), `{kind:"absent"}` for nothing there,
  `{kind:"read", body}` otherwise.

No divergence from what the plan assumes. This phase's module never opens a
path (document, cited target file, schema document) through a bare
`readFileSync`/`openSync` -- every read in `src/gates/citations.ts` goes
through `readRegularFileIfPresent`, and every directory listing (the
one-shot inventory's walk) uses `readdirSync` for the LISTING only (which
cannot block, exactly the precedent `src/gates/pin.ts:137-156` sets) followed
by `classifyEntry` before any content read, mirroring `pin.ts`'s own pattern
rather than inventing a second one.

Also read `src/gates/manifest.ts`, `src/gates/result.ts`, `src/gates/run.ts`,
`src/gates/validate.ts`, `src/commands/gates.ts` in full to confirm the gate
subprocess contract this phase's executable must obey (documented in
`src/gates/run.ts:40-49`): argv is
`<command...> --result <path> --evidence <dir> [--<param> <value> ...]`,
cwd is the runner's own working directory, exit codes are
0 green / 1 red / 20 not-applicable / 21 error, and exactly one
`GateResult` JSON document is written at `--result`. `requiredParameters`
(`src/gates/run.ts:367-377`) auto-adds `base` for any gate whose precondition
kind is `diff-touches`, so declaring that precondition kind is what makes
`--base` mandatory at the RUNNER level; this phase's own module still checks
`--base` independently (see step 5), because R-025's second call site
invokes the same executable directly, outside the runner.

## MECHANISMS.md rows bearing on this phase

Read `MECHANISMS.md` in full (T-005 interim obligation, mandatory for every
M2 phase). Rows that bear on M2-P5, and what each requires here:

- **"Reading a path whose type is not established."** Direct hit: this
  gate's whole hazard class (T-007, M2-D-18) is "a linter over documents it
  does not own, walking a tree supplied by configuration." Requires:
  lstat-then-stat-then-open-only-regular for every read, via the delivered
  `classifyEntry`/`readRegularFileIfPresent`, never a second implementation.
  Closed here by construction (see step 1 above and the hazard self-review
  below).
- **"Deciding what another program will do by pattern-matching the text of a
  file it consumes."** Bears on this phase in a narrow, specific way: the
  citation GRAMMAR is a regex over document prose, which is the shape this
  row warns about, except that here there is no pre-existing "other program"
  whose behaviour the regex has to match -- the citation grammar is a format
  this phase DEFINES, so the row's "two different functions" hazard does not
  apply to grammar recognition itself. It DOES apply to deciding whether a
  changed path "is a configured document": that decision is made with
  explicit path globs stated in committed config (`documents`,
  `citationRequired`, `roots[].match`, `externalRoots[].match`), never
  inferred, matching the row's prescribed tier 2 (PIN the accepted shapes,
  fail closed on anything else).
- **"Parsing another program's reporter output."** Not applicable: this gate
  does not run or parse another program's test-reporter output; `git diff
  --name-only` is consumed the same way `src/gates/run.ts`'s `gitLines`
  already does (line-split, trimmed, filtered).
- **"Atomic file replacement"** and **"Claim file"**: not applicable. This
  gate performs exactly one write, its own `--result` record, refused
  through `refuseOpenForWrite` before the write (matching
  `src/commands/gates.ts`'s `emit`); it never shares a directory with a
  concurrent writer of the same path.
- **"Classifying another program's errors"**: not applicable in the same way
  as the reporter-output row; the only subprocess this gate spawns is `git
  diff`, and its failure (nonzero exit, thrown spawn error) is reported as
  `error` verbatim (fail closed), never pattern-matched into a narrower
  category.
