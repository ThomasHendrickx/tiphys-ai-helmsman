## What this phase built, in one paragraph

M4-P21 left `doctor`, `spawn` and `teardown` not consulting the register, and
said so as its own limit 5. This phase closes that. `src/exclusion.ts` gains a
read-only view of the register (`sharedLockStatus` at src/exclusion.ts:849) and
a verdict for the task-mutating commands (`guardSharedRegister` at
src/exclusion.ts:933). `doctor` gains `CHECK shared-lock`
(src/commands/doctor.ts:1545). `spawn` (src/spawn.ts:906) and `teardown`
(src/teardown.ts:452) ask for that verdict immediately after the local
holdership check and refuse on it. A fleet home with no declaration returns
`off` before any subprocess is spawned, so nothing changes for anyone who has
not opted in.

## Three design decisions, each taken rather than inherited

### 1. The status reader is SEPARATE from `preflightShared`, because a diagnosis must not move what it diagnoses

`preflightShared` (src/exclusion.ts:601) answers a similar question and WRITES
`state/shared-lease.observed.json` on the way, because that file is how the
fencing counter's staleness is measured on one clock. A `doctor` that wrote it
would be changing the fleet it was asked to report on, and a `spawn` that wrote
it before refusing would be a refusal that creates something. `sharedLockStatus`
therefore reads the register through the same `readRegister` and makes no
observation. It does fetch, because `readRegister` fetches, and that is stated
in its header rather than left to be discovered: `.git/FETCH_HEAD` moves and
objects arrive in the object store. No file under the fleet's working tree is
written, which is the property that matters and is the one asserted; what else
a `git fetch` may touch inside `.git` is not enumerated here.

### 2. The guard NEVER generates an environment identity

`ensureEnvironmentId` (src/exclusion.ts:285) writes the identity file when none
is there, which is right for `lock acquire`. `readEnvironmentId`
(src/exclusion.ts:816) is the pure sibling this phase adds, and the guard uses
it. An absent identity file therefore reads as "this environment is not the one
the register names", which is the fail-closed answer AND keeps the refusal free
of side effects.

The heading above is a claim about every call site, so here is the command that
enumerates them and its full output:

```
$ grep -n "ensureEnvironmentId\|readEnvironmentId" src/exclusion.ts src/spawn.ts src/teardown.ts src/commands/doctor.ts src/lock.ts
src/exclusion.ts:285:export function ensureEnvironmentId(fleetRoot: string): EnvironmentIdentity {
src/exclusion.ts:809: * `ensureEnvironmentId` above writes a file when none is there, which is
src/exclusion.ts:816:export function readEnvironmentId(fleetRoot: string): string | undefined {
src/exclusion.ts:954:  const mine = readEnvironmentId(fleetRoot);
src/lock.ts:15:  ensureEnvironmentId,
src/lock.ts:500:  const identity = ensureEnvironmentId(root);
```

The only call of the WRITING form is src/lock.ts:500, which is the lease path
M4-P21 built. The guard's call is src/exclusion.ts:954 and it is the reading
form. **What this does NOT cover:** it is scoped to the five files this phase
reads or changes, so a future call site in another file is invisible to it, and
it says nothing about `writeObservation`, which is a different write on the same
path and is avoided by not calling `preflightShared` rather than by this grep.

### 3. A STALE holder still refuses, and the refusal names the command that resolves it

`judgeByCounter` exists so a lease whose counter has stood still can be taken
over, and that takeover is a LEASE operation. Consulting staleness inside
`spawn` would give it its own opinion about who holds the fleet, which is a
second verdict about one lease from a second place, and it would have to write
the observation file to reach one. So the guard refuses any register that is
held by another environment, stale or not, and the line ends with
`take the fleet over with: tiphys lock acquire --take-over`. Rehearsal steps
R26 to R28 show the gate opening again after a release, so this is a gate and
not a wall.

## Criterion by criterion

### 1. Four statuses, and the fourth is never PASS

`SHARED_LOCK_STATUS_TOKENS` (src/exclusion.ts:787) is the closed set, and the
test compares the token doctor PRINTED against that array rather than against a
list retyped in the test. Two conditions collapse into `unreachable` and the
reason says which: a declaration that is present and unusable, and a register
whose document does not parse. Neither is `free` and neither can be rendered as
`held <envId> until <t>`, because neither yields an environment id or an expiry.

"Never PASS" is a claim about every reachable member of the fourth status, and
what settles it is the capture plus the closed-set test. The capture's own
status words, from the committed file:

```
$ grep -o "CHECK shared-lock [A-Z]*" witness/captures/m4-p22-shared-lock-doctor-cli.txt
CHECK shared-lock PASS
CHECK shared-lock PASS
CHECK shared-lock PASS
CHECK shared-lock PASS
CHECK shared-lock WARN
CHECK shared-lock FAIL
CHECK shared-lock WARN
```

The last three blocks are the three unreachable ones and none of them is PASS.
That is four captured arms of the other statuses and three of this one, not a
proof over every possible reason string, and the test is what carries the
general form: it asserts the status word for every arm it reaches and asserts
that all four tokens were reached, so an arm that started printing PASS would
redden.

The status word is PASS for the first three and WARN for the fourth, under the
condition `shared-lock-unreachable`, which ONLY the `full` profile promotes
(src/commands/doctor.ts:115). The reason to promote it there and nowhere else is
in the table: a fleet that has declared the register and cannot read it refuses
every lease operation, every spawn and every teardown, so it is not ready for
full mode by any reading, and unlike the branch check the remedy is reachable by
the operator.

**THE PROMOTION IS TWO HALVES AND BOTH ARE ASSERTED**, because a promotion wired
to a condition name nothing emits is a guard that cannot go red and reading the
table alone cannot see that. The test asserts the table AND calls
`checkSharedLock` on a fixture in the unreachable state and pins the condition
string it emits.

### 2 and 3. The dangerous state is the one the old guard is already green on

`checkHoldership` (src/task.ts:439) answers "does this process hold THIS
filesystem's lease", and src/lock.ts:77 states that domain honestly. So the
state this phase exists for is: the local lease held by this environment, the
register naming another. The plan says a test that holds neither lease is
refused at review, and it is right: such a test is green without the feature.

The fixture is built from a REAL takeover rather than asserted:

1. environment A acquires, on a clock injected ten minutes behind with an hour
   of duration, so its local lease is still live against the real clock later;
2. environment B observes the register once, arming its own stale measurement;
3. B takes the fleet over once the counter has stood still, which advances the
   register under B's id and CANNOT touch A's lease file, because that file is
   on A's filesystem under the gitignored `state/`.

"Never travels" is the load-bearing half and it is measured rather than
asserted. Rehearsal step S7 lists a freshly cloned fleet home:

```
=== S7 a clone carries no state/ (the local lease cannot travel)
$ ls <A>/env-a
| backlog.md
| charter
| decisions
| package.json
| status
| tasks
exit=0
```

No `state/`, so no lease. The test fixtures assert the same thing at clone time
rather than trusting it, which is why `cloneFleetHome` in all three test files
fails if `state/` is present.

A is then holding a live local lease over a fleet B owns, and `checkHoldership`
answers yes.

**EVERY REFUSAL TEST CARRIES A CONTROL ARM**, and the control is what proves the
old guard is green rather than asserting it. The control removes the opt-in
field from the fleet home's package.json and changes nothing else: not the local
lease, not `TIPHYS_HOLDER_ID`, not the register. Spawn then exits 0 and creates
the worktree. The spawn test then puts the field back and the refusal returns,
so the control left nothing permanently different.

For teardown the control is stronger still, because it is the SAME teardown of
the SAME task: with the field declared it refuses and the worktree, its
uncommitted scratch file, the pool record, the branch and `status: open` all
survive; with the field removed the identical command exits 0, the worktree is
gone and the meta reads `closed`.

## WHAT THIS PHASE DID NOT COVER

Written before the gate evidence, because a reviewer's first check is this
section.

1. **NO REHEARSAL ACROSS TWO MACHINES, TWO CLOCKS OR A REAL REMOTE.** The
   rehearsal's own first section says this at length and it is repeated here so
   a reader of this page alone is not misled: one container, two filesystems,
   one injected clock seam, and a local bare repository over the file transport.
   Whether GitHub serialises two concurrent `--force-with-lease` pushes to one
   ref is inferred from M4-P20's probe and is not measured by anything in this
   phase.
2. **NOTHING HERE RACES.** Every test and every rehearsal step runs one command
   to completion before the next begins. The guard this phase adds is a READ of
   the register followed by a decision, so two environments passing the guard at
   the same instant and then both spawning is a window this phase neither closes
   nor measures. The register's compare-and-swap protects the LEASE and not the
   spawn, so the honest statement is that `spawn` and `teardown` are guarded
   against a register that has already moved, not serialised against one that is
   moving.
3. **A `renew` DOES NOT REFRESH THE GUARD'S VIEW, because the guard has no
   view to refresh.** Each `spawn` and each `teardown` reads the register once,
   at its own start. A takeover that lands while a long spawn is running is not
   noticed by that spawn, and nothing here re-checks.
4. **THE FETCH IS A SIDE EFFECT AND IS NOT TESTED AS ONE.** `sharedLockStatus`
   reaches the register through `readRegister`, which runs `git fetch`, so
   `doctor` moves `.git/FETCH_HEAD` in the fleet home. No test asserts that
   nothing else moves, and no test measures what happens when the fetch
   succeeds and the `cat-file` then fails.
5. **NO TEST MEASURES THE COST ON A FLEET THAT HAS NOT OPTED IN.** The claim
   that the check spawns nothing there rests on reading `sharedLockStatus`,
   which returns before the first git call, and on the promotion test's fixture,
   which is a bare directory with a package.json and no git repository at all.
   Nothing counts subprocesses.
6. **`lock status` IS NOT WIRED TO THE REGISTER.** This phase's files-to-touch
   list names `doctor`, `spawn` and `teardown`, and `tiphys lock status` still
   reports the local lease alone. An operator who runs it instead of `doctor`
   sees the same incomplete picture the M1-P4 guard sees.
7. **`pool` AND `watch` ARE NOT WIRED EITHER.** `tiphys pool destroy` reaches
   the same destructive primitive teardown does, and nothing in this phase
   stops it being run directly by an environment the register does not name.
   The plan does not ask for it and this phase does not do it.
8. **THE UNREACHABLE STATUS CONFLATES THREE CAUSES.** A broken remote, a
   register document that does not parse, and a declaration that is present and
   unusable all print `unreachable <reason>`. The reason distinguishes them in
   prose and nothing in the type does, so a caller that wanted to act
   differently on the three would have to parse a sentence.
9. **A REGISTER HELD BY THIS ENVIRONMENT IS ALLOWED WITHOUT CHECKING THE
   EXPIRY.** The guard compares environment ids and the lease STATE, and does
   not ask whether the register lease it holds has expired by anyone's clock.
   That is deliberate, because comparing another environment's timestamp against
   this clock is the measurement the whole layer avoids, and it means an
   environment whose register lease lapsed long ago still spawns until somebody
   takes the fleet over.
10. **THE INHERITED ENVIRONMENT ID IS STILL ABSORBED RATHER THAN SOLVED.** A
    clone of a fleet whose environment committed `tiphys-environment.json`
