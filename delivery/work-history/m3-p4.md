### VF-1. The validator cannot resolve a cross-document `$ref` as shipped

Plan step 3 requires `schemas/work-history.schema.json` to share the report
schema's `claims[]` and `fix-round[]` definitions BY `$ref` "rather than
restating them", and requires a registered test asserting "both schemas
resolve to the SAME definition object rather than to two equal ones"
(delivery/plan/kernel-plan-m3.md:2817).

As shipped at c7a7ce9, `compileSchema` builds a FRESH Ajv per schema document
and adds nothing else to it (src/validate.ts:616), and `makeAjv` withholds
`loadSchema` on purpose (src/validate.ts:535). So a `$ref` that leaves the
document fails COMPILATION, with `unresolvedRef` or `remoteRef` depending on
whether the reference carries a scheme (src/validate.ts:688).

Consequence: shipping the plan's `$ref` without a change to the compile path
would make `tiphys validate --type work-history` fail on the phase's own
example, which is acceptance criterion 1. The change is recorded under
"Key decisions" below.

### VF-2. The M2-P6 coverage checker has no CLI flag for parity mode

Acceptance criterion 4 says the M2-P6 coverage checker "run in
finding-to-outcome parity mode" exits 0 and exits nonzero on a copy with a row
deleted. `checkFindingOutcomeParity` is an exported function
(src/gates/coverage.ts:599) and the gate CLI accepts only `--result`,
`--evidence` and `--config` (src/gates/coverage.ts:706). There is no parity
subcommand and no flag that reaches that function.

Recorded rather than improvised: adding a flag would edit `src/gates/coverage.ts`,
which is NOT on this phase's declaration. How criterion 4 is discharged instead

### AXIS 2, COST: what a correctness-only measurement would have missed (T-012)

T-012 is explicit that a measurement checking correctness and not cost is not a
partial answer but a wrong one, and that the omission is invisible when the
non-coverage section does not name performance. So, named:

- **The universal-quantifier pattern** is measured above on a long near-miss:
  flat to 256,001 characters. This is the only new pattern with an alternation.
- **The negative-lookahead branch** `^(?:(?!\b(...)\b)[\s\S])*$` is the
  expensive shape in the diff and is included in the same measurement, because
  it is what runs on every accepted `analysis`.
- **`report-parity-arithmetic`** is O(gate results) with constant work each.
  **`final-report-finding-parity`** builds two maps and is O(inputs + rows); it
  is not the O(n squared) nested scan a naive orphan check would be.
- **The companion change costs one extra `ajv.addSchema` per compilation of a
  companion-needing type**, and compilations are cached per (schema, companion
  list) pair, so the cost is paid once per process. Measured indirectly: the
  full suite went from a captured 507 reported tests to 535 with no timeout
  change, and the `suite` gate run completed in 2 minutes 51 seconds before
  this phase's tests existed.
- **NOT MEASURED**: I did not measure `pattern: "\\S"` on a pathological
  subject, because a single-character class with no quantifier cannot backtrack.
  That is a reading, not a measurement, and it is stated as one.

### AXIS 3, FAILURE MODE: what happens when each new guard is wrong

- A companion declared for a type whose schema has no cross-document reference:
  harmless, one wasted `addSchema`.
- A companion NOT declared for a type whose schema does have one: compilation
  fails closed with `unresolvedRef`, and `tiphys validate` exits 1 with a
  diagnostic. It cannot pass silently.
- `report-parity-arithmetic` on a gate result with a non-integer count: returns
  without a violation, because the schema has already rejected it. If the check
  is ever run on an unvalidated instance, this is a silent pass, and it is a
  deliberate belt rather than the guard.
- `final-report-finding-parity` on a document where `inputs` is absent: the
  array is empty, no violation is emitted, and the schema's `required` is what
  rejects it. Witnessed: `tiphys validate` runs derived checks only AFTER schema
  validation succeeds (src/commands/validate.ts:285), so an instance missing
  `inputs` never reaches the check. Same shape.
- **The failure mode I could not close**: a finding dropped from BOTH `inputs`
  and `input-findings`. The two arrays then agree with each other and no
  comparison between them can see it. `src/gates/coverage.ts` answers this with
  a config-stated `expectedUnits` anchor (CR-986); nothing in the plan states
  such an anchor for the final report, so there is none here.

## The converse question, asked of every relation this phase constrains

Three times in M3-P3 a check constrained a relation in one direction while its
documentation claimed both. Every relation below was asked what its converse
admits, and the answer is either CLOSED or stated OPEN with a reason.

| relation | converse | disposition |
|---|---|---|
| `result: green` requires `wrapper-exit-code: 0` | may a NON-green result carry exit code 0? | **OPEN, deliberately.** A wrapper can exit 0 while the author judges the run not green, which is exactly the R-048 silently-dropped-tests shape. Closing it would make the honest record unwritable |
| `discovered == passed + failed + skipped + did-not-run` | may the buckets exceed `discovered`? | **CLOSED.** The check tests equality, and both directions are witnessed |
| counts are non-negative | may a count be negative and still sum? | **CLOSED** by the same check; no keyword in the declared vocabulary reaches it |
| every `inputs[]` id has a row | may a row name an id `inputs` lacks? | **CLOSED** (phantom). May one id have two rows? **CLOSED** (duplicate) |
| a section empty only with `none: true` | may `none: true` sit on top of real entries? | **CLOSED** by the two-branch `oneOf`, whose first branch permits `none` and nothing else |
| `source-pinned: true` requires `pinned-evidence` | may `source-pinned: false` carry `pinned-evidence`? | **OPEN, deliberately.** T-004's rule is that an unpinnable run must be LABELLED, not that a pin may not be recorded. Asserted as accepted in the test so the permissiveness is a decision |
| `contradicts-plan: true` requires `stopped-and-reported` | may a `false` entry name an escalation anyway? | **OPEN, deliberately.** Recording an escalation you did not owe is not a misdeclaration. Asserted as accepted |
