### CV-1: the mechanism, and why the obvious fix was not enough

The obvious fix is "assert the mode string equals full". That closes the
instance contract A demonstrated and leaves the mechanism, which has TWO faces
and only one of them is the mode string.

**Face one, the SUBJECT.** The mode is read out of the brief's own begin marker.
That is deliberate and it is half right: it stops a CALLER pointing the
comparison at a mode the brief never claimed, which is why a `--mode` flag was
rejected (scripts/check-brief-drift.mjs:225). It leaves the EDITOR of the brief
holding exactly the same power. The pin therefore moved OUT of the artifact
under test, to `BRIEF_GATE_BLOCK_MODE` in src/roles.ts:553, and the script now
refuses a disagreement in EVERY mode including `--write`, because `--write` is
the command that turns a narrowed marker into a self-consistent smaller table.

It is not a registry key. `gate-registry.yaml` is closed
(`additionalProperties: false` at schemas/gate-registry.schema.json:8) and its
schema belongs to M3-P2 and is not on this phase's declaration, so a registry
key would be this phase editing another phase's merged contract. That is the
same reasoning that put the mode in the marker rather than the frontmatter.

WHY `full` is not left as a bare literal: the registered test DERIVES from the
registry that the pinned mode selects every gate any mode selects, per mode and
per gate, never by count. Narrowing is then the only direction the value can
move, and the invariant lives in the test rather than in the check, so a future
registry that legitimately grows a mode costs a test failure and a deliberate
update rather than a false red in CI.

**Face two, the COUNT.** `units` was `registry.preflight.length +
selected.length` and `preflight` is mode-independent, so the number had a floor
of three. M2-C-2 rewrites green-with-zero-units and nothing else, so the vacuity
guard could not fire over an EMPTY gate table, and the script header's promise
that "a run that compared ZERO rows becomes error with vacuous: true" was true of
the plumbing and false of the behaviour. `units` is now `selected.length`, which
is what `unitLabel` ("generated brief gate rows compared") names. The gate's
own report moves from 18 to 15 for that reason; the 18 every prior capture
quotes was 15 gate rows plus 3 preflight steps.

Fixing face two closes the empty-subject arm for EVERY mode rather than for the
one contract B used, which is why it is the mechanism fix and the mode pin alone
would not have been.

rendering. So the new check fired on every input `describeDrift` would have

observe. The line was unreachable BY CONSTRUCTION. A test cannot cover an arm
that no input reaches; the remedy is to delete the shadow, not to write a test
against it.

and the witness for both goes vacuous. Redundancy that cannot be observed is
indistinguishable from dead code. REORDERING DOES NOT HELP: it only changes which

### R2-24. WHY IT TOOK SIX PUSHES TO GET ONE RUN, recorded as a process defect

Six pushes preceded this run and every one of them cancelled the run in flight,
because the workflow's concurrency group cancels superseded runs on the same
branch. Four of those pushes were BEACON pushes: appending to this work history
after each cited command and pushing, which is the dispatch-contract discipline
of CLAUDE.md's T-008 section.

**The two rules were in direct conflict and I did not notice.** The beacon rule
protects against a dying agent losing its evidence; the push cancels the only
process that can produce the evidence the round actually owed. Applying the
first mechanically destroyed the second, four times, and the failure is
invisible from inside: each push looked like durability working.

**The resolution, and it is mechanical rather than a matter of remembering.**
COMMITTING and PUSHING are separable, and only the push cancels CI:

- commit locally after every cited command, which is what durability needs, since
  a dying agent's worktree is recoverable and its commits survive;
- push freely while no run matters;
- once a run on the final head is in flight, FREEZE pushes until it reaches a
  terminal state, then push once.

A beacon push is not free when CI is the thing being waited on. That sentence is
the whole lesson, and it cost roughly two hours of wall clock in this round.
