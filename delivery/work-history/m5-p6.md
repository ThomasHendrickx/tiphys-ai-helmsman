## Design decisions (kernel half)

1. **Input.** Two or more phase declarations, positional, in the format the
   scope auditor reads (src/gates/schemas/phase-declaration.schema.json:1). A
   phase's edit set is filesToTouch plus declaredExtras. This is the input the
   two hand pre-passes used (delivery/plan/m2-conflict-pre-pass.md:1 and the
   m5 one on the plan-readiness branch, quoted because it is not on main:
   `delivery/plan/m5-conflict-pre-pass.md`).
2. **Overlap grammar** is the scope auditor's own entry grammar: equal
   strings, or a trailing-slash directory containing the other entry
   (src/gates/scope.ts:517). A directory-contains overlap is named with both
   spellings, `witness/ and witness/x.json (directory contains path)`.
3. **Append-only registries.** Default list is CLAUDE.md convention 5's three
   (test/behaviors.json, gates.manifest.json,
   delivery/requirements/clause-map.json). A shared FILE on the list is an
   `APPEND-ONLY` line, not an `OVERLAP`, and the effective list is printed on
   every verdict run. A shared DIRECTORY is never exempt (src/commands/conflicts.ts:223). `--append-only
   <path>` (repeatable) REPLACES the default, so another project states its
   own registries rather than inheriting this repository's names.
4. **Semantic coupling** is printed as the LAST stdout line of every run:
   overlap, disjoint, input error and usage error alike.
5. **Exit codes:** 0 disjoint, 1 overlap, 2 a declaration could not be used
   (missing, not a regular file, not JSON, wrong shape, duplicated phase id),
   64 usage. Exit 2 prints `NO VERDICT` and no DISJOINT/OVERLAP line.
6. **Duplicate phase id** is exit 2: the same phase given twice would
   otherwise report a total overlap with itself, which is a wrong answer
   rather than a conservative one.

## Design decision: copy, into the PROJECT repository, via `init --project`

- **Copy, not link.** The regime is read from the commit (src/checks.ts:3467).
  A link commits its target text, measured above. A link into
  `node_modules/@tiphys/kernel/` also dangles until an install, and hemma does
  not depend on the kernel package at all.
- **Copy, not resolution through the installed package.** The merge decision is
  deliberately made from the commit being merged (the DV-001 fix recorded at
  src/checks.ts:4870). Resolving `assurance-modes.yaml` from whatever kernel the
  operator has installed would make that decision depend on the operator's
  machine rather than on the reviewed commit. It would also need a change to
  src/checks.ts, which this phase's declaration does not grant.
- **Where.** The consumer is the project repository, so the producer is a new
  arm, `tiphys init --project <repo>`, which writes into an EXISTING git work
  tree and refuses to overwrite. The fleet-home arm is unchanged in what it
  writes, because the measurement shows the fleet home needs none of the four
  items.
- **The copy is pinned.** It is byte-identical to the initializing kernel's
  file. A differing copy is refused, not overwritten, so an upgrade is a
  deliberate act. A symlink at that path is refused by name.
- **I-8 `schemas/` is not copied.** Its only context read is
  src/checks.ts:746, which runs only when an `assurance-modes` DOCUMENT is
  validated with `--context`; the regime read does not use it.
- **I-9 is a project-owned template,** templates/gate-registry.example.yaml.
  Init does not write it: a registry init wrote would be predicates the project
  did not choose, which is the pulse-fleet substitution again. Init REPORTS
  whether the project has one and names the template path in the installed
  kernel.
- **I-10 is not produced.** No kernel code creates `.ctx-*` (grep above).
- **Q-4, the charter.** Two locations, two readers, both from src/:
  `<fleet>/charter/*.yaml` for doctor and brief compose (src/charter.ts:38,
  src/commands/doctor.ts:735), and `<project>/charter.yaml` for the merge
  regime, read from the commit (src/charter.ts:41, src/checks.ts:4750).
  `locateCharters` reports both (src/charter.ts:162). Init writes neither
  (the charter is the project's) and reports both paths.
