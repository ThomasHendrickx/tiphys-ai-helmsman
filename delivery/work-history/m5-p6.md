## Design decisions (kernel half)

1. **Input.** Two or more phase declarations, positional, in the format the
   scope auditor reads (src/gates/schemas/phase-declaration.schema.json:1). A
   phase's edit set is filesToTouch plus declaredExtras. This is the input the
   two hand pre-passes used (delivery/plan/m2-conflict-pre-pass.md:1 and the
   m5 one on the plan-readiness branch, quoted because it is not on main:
   `delivery/plan/m5-conflict-pre-pass.md`).
2. **Overlap grammar** is the scope auditor's own entry grammar: equal
   strings, or a trailing-slash directory containing the other entry
   (src/gates/scope.ts:517). A directory-contains overlap is named with both
   spellings, `witness/ and witness/x.json (directory contains path)`.
3. **Append-only registries.** Default list is CLAUDE.md convention 5's three
   (test/behaviors.json, gates.manifest.json,
   delivery/requirements/clause-map.json). A shared FILE on the list is an
   `APPEND-ONLY` line, not an `OVERLAP`, and the effective list is printed on
   every verdict run. A shared DIRECTORY is never exempt (src/commands/conflicts.ts:223). `--append-only
   <path>` (repeatable) REPLACES the default, so another project states its
   own registries rather than inheriting this repository's names.
4. **Semantic coupling** is printed as the LAST stdout line of every run:
   overlap, disjoint, input error and usage error alike.
5. **Exit codes:** 0 disjoint, 1 overlap, 2 a declaration could not be used
   (missing, not a regular file, not JSON, wrong shape, duplicated phase id),
   64 usage. Exit 2 prints `NO VERDICT` and no DISJOINT/OVERLAP line.
6. **Duplicate phase id** is exit 2: the same phase given twice would
   otherwise report a total overlap with itself, which is a wrong answer
   rather than a conservative one.

## Hazard self-review

- **false-disjointness** (zero overlap read as zero coupling). Attacked:
  could a disjoint result omit the obligation? The obligation is printed by
  the single `finish` exit helper (src/commands/conflicts.ts:245) and every
  return in `cmdConflicts` goes through it; two witness members remove it or
  bypass it on the disjoint exit and both redden. Could an input error read
  as disjoint? Witnessed by four structurally different bad inputs (absent,
  a directory, YAML-not-JSON, JSON missing filesToTouch) plus a duplicate id,
  all exit 2 with NO VERDICT and no DISJOINT line. Could a directory entry
  hide an overlap? Directory-prefix detection is its own witnessed member,
  and a shared directory is not exempt even when it contains an append-only
  file: `appendOnly` is computed on the concrete path and is false whenever
  that path is a directory (src/commands/conflicts.ts:223).
- Found nothing further. Not attacked: paths that are equal only after
  normalisation (`./a` versus `a`, case folding). The command compares
  literal strings, as the scope auditor does; a declaration writing the same
  file two ways would be reported disjoint. Left as an open question for the
  reviewer rather than claimed safe.
- hidden-bootstrap-handwork and self-hosted-success belong to the hemma half
  and are not exercised here.
