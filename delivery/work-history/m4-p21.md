## What this phase built, in one paragraph

A second exclusion layer above `src/lock.ts`, declared per fleet home and off
by default. `src/exclusion.ts` is new. A fleet home opts in through
`tiphys.sharedExclusion` in its own `package.json`; with the field absent
nothing below is entered and no subprocess is spawned. When it is present,
`acquire`, `renew` and `release` first ask a compare-and-swap register on a
dedicated git ref of the fleet's shared remote, and only a won verdict reaches
the local lease. The register's value is a commit whose only file is
`lease.json`, carrying an environment id, a monotonic fencing COUNTER, and the
lease window. Every write is `git push --force-with-lease=<ref>:<exact sha>`.

## The three findings from M4-P20 that are implemented rather than remembered

M4-D-11 was prototype-blocked and M4-P20's probe closed it. Three of its
findings are load-bearing and each one is now a line of code rather than a
note.

1. **Only `refs/heads/*` is pushable.** CLAUDE.md:1146 records it and the
   dispatch asked for a re-measurement rather than trust. Re-measured on this
   branch, 2026-09-17, against the real remote, one commit, four target refs,
   git exit code captured per push:

   ```
   === refs/tags/m4p21-probe ===
   error: RPC failed; HTTP 403 curl 22 The requested URL returned error: 403
   git exit=1
   === refs/notes/m4p21-probe ===
   error: RPC failed; HTTP 403 curl 22 The requested URL returned error: 403
   git exit=1
   === refs/tiphys/lease ===
   error: RPC failed; HTTP 403 curl 22 The requested URL returned error: 403
   git exit=1
   === refs/tiphys-probe/lease ===
   error: RPC failed; HTTP 403 curl 22 The requested URL returned error: 403
   git exit=1
   ```

   The third row is the one that matters: **the ref criterion 2 names
   literally, `refs/tiphys/lease`, is refused by the remote this kernel is
   built against.** The `refs/heads/*` arm was NOT re-pushed as a probe,
   because this container cannot delete a remote ref (CLAUDE.md:1103) and a
   probe branch would be undeletable litter; the arm is instead witnessed by
   this phase's own branch push, which is an ordinary `refs/heads/*` push and
   succeeded. So the default register ref is `refs/heads/tiphys/lease`, a
   BRANCH, configurable through the declaration for a remote with different
   rules. **The consequence, stated here rather than left to be discovered:
   the register is visible in branch listings and is subject to any
   `refs/heads/**` ruleset the remote carries, including branch protection and
   required reviews. A protected-branch rule that covers it would make every
   acquire fail closed.**
2. **The expectation must be an explicit sha.** `casWrite` at
   src/exclusion.ts:451 emits only `--force-with-lease=<ref>:<sha>` and never
   the bare form, which M4-P20 measured clobbering a live holder with exit 0.
3. **Nonzero does not mean "I lost".** The compare-and-swap result has THREE
   states. A push failure with git's own `! [rejected]` marker is a LOSS; a
   failure without it re-reads the register and reports INDETERMINATE unless
   the re-read settles it.

## The design, criterion by criterion

### 1. Declaration, not inference

`readSharedExclusion` reads `<fleet>/package.json`. Absent, or `false`,
returns before anything else happens. `tiphys init` writes no `tiphys` section
at all unless `--shared-exclusion` is passed (src/commands/init.ts:88), so
every fleet home created today behaves exactly as it did.

**A declaration that is PRESENT and unreadable is refused, not treated as
absent.** Reading a typo as "off" would silently downgrade a fleet to
local-only exclusion and print nothing, which is hazard H-B in the place it
would be hardest to notice. `test/lock.test.ts` carries both arms, because
only the pair distinguishes fail-closed from refuse-everything.

### 3. Environment identity is not the machine

A random id generated once by `ensureEnvironmentId` and written to
`<fleet>/tiphys-environment.json`, which sits outside the gitignored set at
src/fleet.ts:29, so it is trackable: an environment that commits it keeps its
identity across a reclaim, and a clone of that commit reads the same id. The
criterion names its own check and it is implemented literally: the test greps
`src/exclusion.ts` for `hostname`, the running program's identifier, the
kernel virtual filesystem prefix and the signal-sending call, and requires
zero hits. **The grep is given a control**: the same check is run against
`src/lock.ts`, which does carry `hostname`, so a grep that could not find
these tokens would itself redden.

**THE COLLISION THIS DESIGN HAS, NAMED RATHER THAN HIDDEN.** The criterion
requires the id to TRAVEL with a clone. It follows that a second environment
cloned from a fleet whose first environment COMMITTED its id inherits that id
and is not distinguishable from it. The design absorbs this rather than
depending on the ids differing: **`acquire` refuses a register that is held
and not stale whatever environment id it names.** An acquire means "I hold
nothing", so a live register lease refuses it, exactly as the local lease
already refuses a second acquire in one fleet home. Only `renew` and
`release`, which claim to BE the holder, compare the id. The M4-P20 witness
that clones from a pushed fleet exercises precisely the inherited-id case and
is refused.

### 4, 5 and 6. The counter is the signal, and the command says so

`isExpired` compares a lease timestamp against the LOCAL clock
(src/lock.ts:220). Two environments bring two clocks, so that comparison is
the one this layer must not make. `judgeByCounter` at src/exclusion.ts:553
judges a holder stale only when the register's sha AND counter are the ones
this environment first saw, and that much of ITS OWN time has passed: two
readings of one clock, never one reading of two. Any advance of the counter
resets the measurement, which is what makes a renewing holder safe however far
its clock is from the observer's.

Where the register is reachable the counter decides and every line the command
prints carries `signal=counter`. Where it is not reachable there is no counter
to read, only the local clock, and the command prints `signal=clock` and
REFUSES. So a run can always say which of the two reached its verdict, which
criterion 6 requires by name. That "always" is a counting claim and here is
what settles it: every verdict this layer produces is one of eleven `line:`
constructions in `src/exclusion.ts`, and all eleven carry the marker.

```
$ grep -c "line:" src/exclusion.ts
13
$ grep -oF "signal=" src/exclusion.ts | wc -l
13
```

Two of each are the two `line: string;` type fields and the two occurrences in
this module's header comment, leaving eleven constructions and eleven markers.
The three failure lines `src/lock.ts` builds embed `casFailureLine`, which
carries the marker too.

The skew is injected through `TIPHYS_LOCK_TEST_NOW_MS`
(src/commands/lock.ts:120), which feeds the EXISTING `nowMs` option
(src/lock.ts:571). No system clock is touched anywhere. A value that does not
parse throws rather than falling back to the real clock, because a seam that
quietly ignored its input would make a skew witness green while measuring no
skew.

### 7. Fail closed on an unreachable register

The shared verdict is asked for BEFORE the local lease file is touched
(src/lock.ts:491 and the acquire path above it), so an unreachable register
leaves no local lock behind. If the register is reachable but the write is
lost or indeterminate AFTER the local lease was created, the local lease is
rolled back through the same mutation primitive and the command exits
nonzero. **The rollback is one more mutation and it can itself fail**, for
instance against a stale claim file; nothing here retries it or reports it
separately, so a failed rollback leaves a local lease this environment does
not believe it holds. That residue is listed in the section below rather than
claimed away.

### 8. Release goes through the same compare-and-swap

A release preflights the register first. A release by an environment the
register does not name is refused before any write, so the register sha is
byte-identical. A release by the holder advances the counter and publishes a
`free` document; it does NOT delete the ref, because this container cannot
delete a remote ref at all (CLAUDE.md:1103), so a tombstone is the only form
of release that works on the remote the kernel targets.

**The two clock members are the pair the plan asks for and they are
structurally different.** The fast-challenger witness reddens under a
staleness rule that compares the holder's expiry against the CHALLENGER's
clock, which is the implementation a reviewer would most likely accept. The
slow-renewal witness reddens under that same rule AND under a second, entirely
different defect: an observation that is not re-identified against the
register's current value, so a write that moved the register no longer resets
the duration measurement. A tolerance widened instead of a counter survives
neither.

**The register write consumes another program's output, so every spec cites a
real capture.** `witness/captures/m4-p21-shared-register-git-contract.txt` is
a forced contention on a bare repository, captured 2026-09-17 with git 2.43.0.
It records four things the design depends on: `git commit-tree` exits 128 with
`fatal: empty ident name` when no identity is in scope, the exact-sha
`--force-with-lease` form is ACCEPTED against the value the register holds and
REFUSED with `! [rejected] ... (stale info)` against any other, `ls-remote`
against a path that is not a repository exits 128 while `ls-remote` for an
absent ref exits 0 with empty output, and the FIRST stderr line of every push
in this container is a push-negotiation warning that is byte-identical on the
accepted and refused arms. **That last fact is why the module selects git's
own `! [rejected]` marker rather than the first line**, which is the defect
M4-P20 found in its own probe and this phase inherited rather than repeated. A
named test reads the capture and reproduces the accept and refuse arms against
a live scratch repository.

The first of those four also changed the code: `git commit-tree` refuses
without an author and CI runners carry no git identity (CLAUDE.md standing
warning 5), so the register commit is written under a command-scoped
identity, and a test pins it equal to the one `tiphys init` already uses so a
drift reddens here instead of only on a runner.

### The anti-vacuity control for the two clock members

Both members assert a REFUSAL, so a stale window that could never be reached
would make them pass while proving nothing. `the stale window is reachable
when the fencing counter does not advance` is the same sequence with the
renewal removed: the counter stands still, the window elapses on the
observer's own clock, and the takeover is ALLOWED, with the register advancing
to counter 2 under the taking-over environment's id. So what refuses in the
member above is the renewal and not an unreachable window.

## The mechanism, not the finding

This phase had no review finding to fix, so the fix-round contract applies to
the one place it has teeth here: the C-2 collision found while wiring the
layer in.

**The finding** would have been "`SharedNote.signal` reddens the C-2
structural inspection of `src/lock.ts`". **The mechanism is:** any identifier
this phase introduces into `src/lock.ts` is checked against a blunt
case-insensitive grep that file carries for a different reason
(test/lock.test.ts:534, M1-P3 criterion 10), and the grep's vocabulary
overlaps ordinary English. The derivation is the grep itself, run over the
file as this phase leaves it:

```
$ grep -niE "pid|process\.kill|/proc|\bkill\b|signal" src/lock.ts
$ echo $?
1
```

Zero hits, exit 1. The resolution was to carry the verdict as TEXT on
`SharedNote` and keep the classification in `src/exclusion.ts`, which no such
grep covers, rather than widening the C-2 guard to let a new word through.
Widening it would have been the instance fix; moving the vocabulary out of the
file is the mechanism fix.

**What the derivation does NOT cover:** it is scoped to `src/lock.ts` alone,
because that is the only file in this phase's diff carrying such an
inspection. `src/commands/lock.ts`, `src/commands/init.ts` and
`src/exclusion.ts` have no equivalent grep over them, so an identifier that
would offend a future one is not detected by anything here. The check for
`src/exclusion.ts` is the C-2 test this phase adds, and its vocabulary is the
four tokens criterion 3 names and no others.

## WHAT THIS PHASE DID NOT COVER

Written before the gate evidence, because a reviewer's first check is this
section.

1. **No two-environment rehearsal against a REAL remote.** Every register in
   every test is a local bare repository reached over the file transport. The
   remote this kernel targets refuses three of the four ref namespaces probed
   above and a local bare repository accepts all of them, so the two are not
   the same configuration. Whether GitHub honours `--force-with-lease`
   atomically under genuine concurrent pushes from two hosts is INFERRED from
   M4-P20's probe and is not measured here. M4-P22 criterion 4 is the phase
   that owes that rehearsal.
2. **Branch protection over the register ref is untested.** The register is a
   branch, so a `refs/heads/**` ruleset can cover it. Nothing here exercises a
   protected register, and the failure mode would be every acquire failing
   closed with a push refusal rather than a lease refusal.
3. **The inherited environment id is absorbed, not solved.** A clone of a
   fleet whose environment committed `tiphys-environment.json` carries that
   environment's id. Acquire refuses regardless, so exclusion holds, but
   `renew` and `release` from such a clone would be accepted as the holder's.
   Nothing in this phase detects that case or warns about it.
4. **Register history is not pruned.** Every write is a parentless commit
   force-pushed over the ref, so the superseded commits become unreachable
   objects on the remote and are left to its own garbage collection. No test
   measures how many accumulate over a long-lived fleet.
5. **`doctor`, `spawn` and `teardown` do not consult the register.** They are
   M4-P22's files and were not touched. Until that phase lands, a fleet with
   the field declared gets cross-environment exclusion on the lock commands
   only, and `tiphys spawn` still verifies local holdership alone.
6. **No concurrency test races two acquires in true parallel.** The group-3
   member A witness starts both acquires before either resolves, but every git
   call in this module is `spawnSync`, so the two interleave at the register
   rather than inside one process. The single-winner postcondition is
   interleave-independent, which is why this is recorded as a limit of the
   measurement rather than a gap in the property.
7. **The indeterminate arm of the compare-and-swap is not directly
   witnessed.** It is reached in the unreachable-register mutant run, where a
   push fails with no rejection marker, but no test constructs a transport
   failure at exactly the push step with the register otherwise readable, so
   the re-read that is meant to settle it is exercised only in the arm where
   the re-read also fails.
8. **The observation file is not protected against a hand edit.** It lives
   under the gitignored `state/` prefix and an operator who edits its
   `firstSeenMs` backwards can make a live holder look stale to this
   environment. The register's compare-and-swap still decides the outcome, so
   the consequence is a refused takeover rather than a double hold, but the
   file is not validated beyond its shape.
9. **A FAILED ROLLBACK IS NOT HANDLED.** When the register write is lost after
   the local lease was created, the local lease is rolled back and the command
   exits nonzero, but the rollback's own outcome is discarded. If it fails,
   this environment is left holding a local lease it has just reported it does
   not hold. Nothing here retries, reports or tests that path.
10. **macOS is not exercised.** Every capture is from this Linux container.
