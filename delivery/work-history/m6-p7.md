## Step 2: adapters/codex/review.ts maps the grant

- Flags used, each in the help above: `--json`, `--model`, `--sandbox`,
  `--ephemeral`, `--ignore-user-config`, `--ignore-rules`, `-c`. The named test
  checks every flag in the argv against the committed help text
  (test/fixtures/review-dispatch/codex-exec-help.txt).
- `-c` keys, each checked against the installed CLI rather than memory, by
  giving it a wrong value and reading its own error (unknown keys are
  silently accepted, exit 0, so a key is only proved by a type error):
  `approval_policy` ("expected one of `untrusted`, `on-failure`,
  `on-request`, `granular`, `never`"), `web_search` ("expected one of
  `disabled`, `cached`, `indexed`, `live`"), `sandbox_workspace_write.
  network_access` / `.exclude_slash_tmp` / `.exclude_tmpdir_env_var`
  ("expected a boolean"), `shell_environment_policy.inherit` ("expected one of
  `core`, `all`, `none`"), `shell_environment_policy.exclude` ("expected a
  sequence").
- Bounds measured offline with `codex sandbox` (no API call), same settings:
  a write in the working directory succeeded; writes to a sibling directory,
  `/tmp` and `$TMPDIR` failed "Read-only file system"; `curl` and node https
  failed DNS. Controls: `workspace-write` defaults wrote all four places; with
  `network_access=true` curl reached the network (HTTP 403 from the proxy).
  `codex debug prompt-input` renders "Network access is restricted" and
  "Approval policy is currently never" under the mapping.
- A project `.codex/config.toml` in the reviewed tree (sandbox
  `danger-full-access`, network on) was not loaded: the render stayed
  `read-only` without overrides and the mapped values with them.
- WHAT IT CANNOT BOUND (also in the code comment): the command list (the
  sandbox bounds what a command touches, not which program runs; execpolicy
  rules are files, and `allow` there means outside the sandbox), and reads
  (whole filesystem, as for the Claude executor). The grant was not widened.
- Tier map from `GET /v1/models` (200, 135 ids) intersected with
  `codex debug models --bundled`: strongest `gpt-6-astra`, cheaper
  `gpt-6-luna`. Family `openai` for the prefix `gpt-`.

## Kernel: the harness's own credential (needed for steps 3 and 5)

Measured: `codex exec` in the scrubbed environment gets `401 Unauthorized:
Missing bearer or basic authentication` on every attempt; the proxy supplies
no OpenAI credential (`curl /v1/models` with no header: 401). With
`OPENAI_API_KEY` set it still sent no bearer (capture
test/fixtures/review-dispatch/codex-without-key.stream.jsonl). The binary
names `CODEX_API_KEY`; with it set the run authenticated. So
`ReviewExecutor` gains an optional `environment` (name + reason), refused
before anything is created by the existing `refuseExtraAllowlist(...,
"reason-required")` (a pull-request credential, code-execution variable or
proxy is refused), and joined to the scrubbed environment AFTER `npm ci`. The
argv excludes it from every command the reviewer runs; the capture shows
`key absent` from inside the sandbox.
