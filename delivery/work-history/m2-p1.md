**WHAT THIS DERIVATION DOES NOT COVER**, stated because a search whose scope is
wrong returns an empty result indistinguishable from an absence of defects:

1. It searched `src/commands/` only, which is where flags are PARSED. A
   destructive operation reachable without a flag, or a flag parsed elsewhere,
   is outside it. `src/pool.ts` and `src/teardown.ts` mention the same flags
   (they construct git argv from them) but parse none; that was checked by the
   wider `grep -rn -- '--discard|--force|--delete-branch-force' src/`, whose
   hits outside `src/commands/` are all comments or git argv construction.
2. It does not cover `scripts/`, which holds shell harnesses, nor anything a
   gate subprocess may invoke. Those are not kernel CLI commands and the
   manifest field is documented as a list of CLI commands and module paths.
3. It cannot see a command that will become destructive LATER. That is the
   half kernel plan M2 section 2 item 11 hands to M3-P6's implementer brief
   ("add the command to the manifest's destructiveCommands list"), and M2
   claims only the machine-readable list.
