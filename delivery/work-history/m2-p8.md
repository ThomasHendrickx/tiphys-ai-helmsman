## Deviations from the plan section

1. **--allow-pr-credentials is a SpawnOptions field, not a CLI flag.**
   The spawn CLI's flag parser lives in src/commands/spawn.ts, which is
   NOT on this phase's files-to-touch list (the plan's own list omits
   it), and touching an off-list file fails the scope audit. The seam
   is therefore exposed and witnessed at the library boundary
   (spawnTask), which is also where every M4-era adapter caller will
   sit. The CLI wiring is a four-line edit in src/commands/spawn.ts
   left to the orchestrator to authorize explicitly; nothing in M2
   consumes the flag.
2. **The scrub root is removed after a completed launch.** The plan
   says the redirect targets live in the task directory; it does not
   say for how long. They are ephemeral on the completed path because
   the delivered task-directory contract (spawn tests snapshot
   tasks/<id> as a flat set of record FILES) breaks on a lingering
   directory, and because an empty redirect tree serves nobody after
   both children have exited. They persist on an incomplete outcome for
   inspection.
3. **credential-token's token-present arm reports error.** The 1.4
   table's "green with owner action A-3" describes the state AFTER the
   A-3 witness exists; shipping a green path now would require deriving
   assertions from invented API responses, which step 7 and T-003
   lesson 4 forbid. Fail closed until the captures exist.
4. **A fourth red-class member (widened allowlist) was added** beyond
   the criterion's literal two directions, because the W6 defang proved
   the token tripwire had no reddening witness without it (recorded in
   the red-witness table; the one-witness-is-not-a-class rule applied
   to this phase's own first attempt).
5. **The gates are a module with a main guard, not a tiphys
   subcommand**, because M2-D-07 reserves src/cli.ts to M2-P1; this is
   the same pattern the plan prescribes for M2-P7's adapters.
