Fact 2, a defect in the brief's toolchain location. The brief says install to
`$HOME/.toolchains` and never under /tmp, because an unprivileged-uid test
cannot traverse /tmp/claude-0. In this container `HOME=/root` and /root has
the same property:

```
$ echo $HOME; ls -ld /root /tmp/claude-0 /home/user/.toolchains
/root
drwx------ 16 root root 4096 Sep 30 10:00 /root
drwx------  8 root root 4096 Sep 30 11:42 /tmp/claude-0
drwxr-xr-x  3 root root 4096 Sep 29 22:24 /home/user/.toolchains
$ setpriv --reuid=65534 --regid=65534 --clear-groups sh -c '/root/.probe-trav/true; echo exec=$?'
sh: 1: /root/.probe-trav/true: Permission denied
exec=126
$ setpriv --reuid=65534 --regid=65534 --clear-groups sh -c '/tmp/claude-0/probe-trav/true; echo tmpexec=$?'
sh: 1: /tmp/claude-0/probe-trav/true: Permission denied
tmpexec=126
```

(`/bin/true` copied into each directory as the probe, removed afterwards.)
So a cloud session whose hook installs Node into `$HOME/.toolchains` puts the
interpreter where test/gates.test.ts and test/doctor.test.ts
`runCliUnprivileged` cannot spawn it; their traversal grant covers only paths
under `os.tmpdir()`. I did not change the default (the brief fixes it).
What I did instead, and it is an open question for the orchestrator: the
toolchain root is one overridable variable (`TIPHYS_TOOLCHAINS_DIR`, default
`$HOME/.toolchains`), and the script prints a one-line warning when an
ancestor of the chosen toolchain is not traversable by other users.
