## Step 2: scripts/setup-env.sh, its tests, and the SessionStart hook

Added `scripts/setup-env.sh` (bash, `set -euo pipefail`), steps in order:
full clone (`git fetch --unshallow origin` when `--is-shallow-repository`
prints true, then re-read and refuse if still shallow); Node floor from
`package.json` `engines.node` (only `>=X[.Y[.Z]]` accepted, anything else is
refused); below the floor, `$TIPHYS_TOOLCHAINS_DIR` (default
`$HOME/.toolchains`)/node-v26.6.0-linux-x64 is used, downloaded when absent
from `$TIPHYS_NODE_DIST_URL` (default https://nodejs.org/dist/v26.6.0) into a
staging directory INSIDE the toolchains directory, sha256-verified against
the tarball's own line in SHASUMS256.txt, extracted, then moved into place;
its bin goes first on PATH and, when `CLAUDE_ENV_FILE` is set, one
`export PATH="<bin>:$PATH"` line is appended (not repeated on a re-run);
`npm ci` unless every entry of `node_modules/.package-lock.json` equals
`package-lock.json`'s and every non-optional lockfile package is present
(byte equality would never hold: the hidden lockfile omits the 18 optional
platform packages of `typescript`, measured 35 lockfile entries against 17);
`npm run build` always, then `dist/` must exist. Every step fails with one
`setup-env: <step>: <reason>` line and exit 1. Tool output goes to stderr,
status lines to stdout, last stdout line is the summary.

Deviation, stated: the brief's text has no `TIPHYS_TOOLCHAINS_DIR`. I added it
as the only way to avoid the /root trap measured in step 1 without changing
the brief's default, plus the traversal warning. Open question for the
orchestrator: which default the cloud hook should use.

`.claude/settings.json`: SessionStart, matcher `startup|resume`, timeout 600,
command `if [ "$CLAUDE_CODE_REMOTE" = "true" ]; then bash
"$CLAUDE_PROJECT_DIR/scripts/setup-env.sh"; fi`. Locally CLAUDE_CODE_REMOTE is
unset, so the command is a no-op that exits 0.
