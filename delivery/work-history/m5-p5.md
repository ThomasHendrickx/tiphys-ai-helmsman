part of it is inside an HTML comment, when it sits under a heading whose text
matches superseded, retired, archived, historical, history, non-binding, not

level), or when its paragraph contains non-binding, not binding or no longer
binding. Headings inside fences are not headings. Before choosing the labels I
checked the three pruned files: `grep -niE "no longer binding|non-binding|not
binding|<!--"` finds only the two generated-gate-block markers in CLAUDE.md and

### What the derivation did NOT cover

- It is textual. It finds guards that report through `fail(`, `f.push(`,
  `missing.push(`, `findings.push(` or a returned literal array. A guard that
  reports some other way, for example by throwing, is not in the output. A
  scan of the diet section for `throw` printed nothing.
- It covers test/retirement-inventory.test.ts only. The checker script
  scripts/check-retirement-inventory.mjs has its own guards for the M4-P23
  rows. They are a different mechanism (command execution with an allowlist)
  and this round did not change them.
- The label lists are closed. A paragraph that disclaims itself in other words
  ("kept for reference", "obsolete") still reads as binding. A reviewer who
  finds such a phrase in a pruned file should add it to the list.
- The `enforced-by` file check is textual: a test file that names the script
  in a string counts as running it. The member-A fixture builds the unrelated
