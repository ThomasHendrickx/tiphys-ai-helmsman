### The detector predicate was WRONG on its first run, and this is the record

The first version counted gate ids ANYWHERE in the prose. Run against the real
document it went red immediately:

```
AGENTS-REFERENCES 4 distinct gate ids occur in the body (check-agents-references, check-dual-review, red-witness, scope), which is a gate list
```

`scope` is a gate id AND an ordinary English word, and "the red-witness rule" is
a concept this brief must be able to name. The predicate was forbidding the
document from MENTIONING things, which is not what section 1.5 forbids. Fixing
the DOCUMENT to satisfy it would have been the instance fix and would have left
a detector that a rewording defeats while a pasted table stays possible.

The predicate is now the LINE SHAPE: distinct ids on lines carrying a list
marker or a table pipe. That is what restated data looks like. Measured, the
body carries ZERO enumerative lines:

```
$ awk '/^---$/{n++;next} n>=2' AGENTS.md | grep -cE '^[ \t]*([-*+][ \t]|[0-9]+[.)][ \t]|\|)'
0
```

TWO RESIDUES, written into the source at the thresholds and repeated here. A
table REWORDED so the ids become descriptions is a semantic relation no
fixed-token detector decides. A restatement written as flowing PROSE rather
than as a list evades the line predicate. Both are section 2.6 reason 1 and the
instrument for both is the hazard review contract, not this script.
