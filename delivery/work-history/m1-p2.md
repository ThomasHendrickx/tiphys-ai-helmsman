## Key decisions and the why that is invisible in the diff

1. Machine identity is the plan's example constant verbatim: Tiphys Fleet <fleet@tiphys.invalid>, exported from src/commands/init.ts and set as command-scoped GIT_AUTHOR_*/GIT_COMMITTER_* variables on the bootstrap commit invocation only (EXT-F-02 Option B). init runs git init, git add -A, git commit as child processes; only the commit gets the identity env; user and global git configuration are never read for identity and never written.
2. Durable directories (charter/, decisions/, tasks/) each get an empty .gitkeep so the bootstrap commit actually tracks them: git cannot track an empty directory, and without a tracked entry the durable layout (SC-002, D-4) would not survive a clone of the fleet repo. The ignored ephemera (state/, worktrees/, projects/) get no keep file on purpose: they are not repository content and are recreated locally. Declared as deviation 2.
3. git init uses --initial-branch=main for a deterministic branch name independent of the machine's init.defaultBranch (which the empty-HOME criterion 7 environment cannot provide). The plan says only "git init"; branch name choice is implementation detail, recorded here.
4. init distinguishes "already initialized" (any fleet marker present: a layout directory, backlog.md, or .git) from "not empty and not a fleet home" (anything else in a non-empty directory); both exit 1, only the former prints "already initialized". The plan requires init to work in "an empty or absent directory", so a foreign non-empty directory is refused rather than overwritten.
5. Doctor check names are stable single tokens in step 3's listed order: node, git, gh, layout, remote, lock, beacon, identity. WARN conditions carry the promotion identifiers from the plan's profile table: gh-missing, remote-missing, beacon-absent, plus identity-unset (promoted by no M1 profile). Profile promotion appends "(required for profile <p>)" to the promoted line.
6. Doctor's lock check reads state/orchestrator.lock (the M1-P3 path fixed by the plan) as a file only: absent = PASS "no lease present"; valid JSON with holderId and expiresAt = PASS reporting holder and expiry (with an "(expired)" annotation when past); unparseable or missing fields = FAIL. No process probing anywhere (C-2); a structural grep for process.kill, /proc, and pid over the three new src files is clean.
7. Doctor's beacon check reads state/watcher.beacon (FM-043 convention, P5's path): absent = WARN "watcher not running or not scheduled" (PR-206 wording); present = PASS with mtime age, freshness threshold explicitly deferred to the M1-P5 liveness guard per the plan.
8. Doctor reads the kernel's engines.node range from the kernel's own package.json via the same walk-up used by src/version.ts, reimplemented locally in doctor.ts because src/version.ts is not in this phase's files-to-touch and does not export its finder. Range parsing accepts the ">=N" form the kernel uses and FAILs on anything it cannot interpret (never green by guessing).
9. The remote check tests for .git in the fleet root rather than git rev-parse --is-inside-work-tree, so a fleet-shaped directory nested inside some unrelated outer repository is not misread as a fleet repo.
10. C-1 note: no P2 check reads task currency at all; the module doc in doctor.ts records that any future task-currency check must read tasks/<id>/meta.json and turn-end files only, never a log tail. src/fleet.ts documents the same for the accessors it will grow.
11. Tests run the CLI through the source entry (node bin/tiphys.ts, the plan's invocation form) with temp directories under os.tmpdir(), cleaned via t.after. The criterion 8 witness builds a deterministic gh-free PATH (a temp bin dir containing only a git symlink) so it holds even on runners where gh is installed.
12. Node-floor handling in tests (inherited warning 1): on a runner below the Node 26 floor, doctor's node check legitimately FAILs, so the two exit-0 assertions (criterion 4's and criterion 8's generic-profile exit 0) are floor-gated tests that skip locally with a recorded reason and run on CI (Node 26, the authority). All line-format, per-check, and promotion assertions run everywhere unconditionally, and the main healthy-fleet test additionally asserts the exact node-check status and exit code implied by the running Node version, so it is falsifiable on both sides of the floor.
