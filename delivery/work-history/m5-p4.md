How the harnesses work, since text presence is explicitly not enough:

- p4-ci-steps: the test parses gates.yml, takes the one `gates`-job step whose
  `run:` invokes each script, and EXECUTES that `run:` text with
  `bash --noprofile --norc -eo pipefail -c` (the runner's default shell) in a
  committed fixture repository, clean and with the deliberate violation (a NUL
  byte in a tracked file; two tuition files sharing T-001). It evaluates the
  step's `if:` for both `pull_request` and `push` with a fail-closed
  evaluator, and refuses `continue-on-error` on the step or job and a matrix
  on the job. Each violation is shown to leave the OTHER step green, so each
  step is reddened by its own property. Three defangs applied to the workflow
  text are each shown to be detected: `|| true`, `continue-on-error: true`,
  and an `if:` narrowing to `pull_request`.

  argument and the harness's `local dir=` line for that bundle. Four
  widenings are each shown to redden (the bundle directory, a `**` glob, the
  evidence root, a second path line), as are a missing retention, a 90-day

- p4-next-action: the real script runs as a subprocess against a scratch clone

## Pre-submit hazard self-review

- workflow-text-guard ("CI appears wired because a string exists while the
  step cannot fail the job"). Attacked: `|| true` on the run line,
  `continue-on-error` on the step, an `if:` narrowing to one event, the step
  deleted (W1), the step moved to another job (the harness only looks inside
  `jobs.gates`, so a moved step reads as found 0, same as W1). Not attacked: a
  `shell:` override (the harness refuses any `shell:` rather than emulating
  it), a job-level `if:` on `gates` (not evaluated; the job has none today),
  and GitHub's own expression engine, which the fail-closed evaluator
  approximates for the two forms used and throws on anything else. The step
  runs on Linux in CI; the harness runs wherever the suite runs, including
  macOS smoke, where it has not been observed yet (CI-deferred).
- evidence-leak ("uploading the evidence directory publishes captured
  output"). Attacked: directory, evidence root, `**` glob, a second line.
  Checked that summary.json itself holds paths, not capture contents
  (src/gates/run.ts:2269). Residual: the summary's `detail` strings are
  gate-authored one-liners; a gate that put a secret in its detail would leak
  it. That is a property of every gate's detail text, not something this
  phase can bound, and it is stated rather than claimed away.
- descriptive-only-fix ("the mode list is corrected once but can silently
  drift again"). Attacked: every single-id removal, a new registry gate, a
  renamed gate, an unknown mode entry, a gate losing `full`. Residual: the
  guard covers `full` only; see Open questions.
