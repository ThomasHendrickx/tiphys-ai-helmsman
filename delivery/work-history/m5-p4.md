### CR-001 (medium): the harness ran CI steps under the wrong shell

**Mechanism.** The harness executes a workflow step's `run:` text under a
shell it CHOSE rather than the shell the runner uses for that step. It chose
`bash --noprofile --norc -eo pipefail`. The runner uses `bash -e {0}` for a
step with no `shell:` on ubuntu, with no pipefail, and run 35834743824 logs
`shell: /usr/bin/bash -e {0}` for these steps. So a pipeline's status in CI is
its last command's, and `run: node scripts/check-authored-bytes.mjs | cat` is
green in CI on a real violation. The harness, with pipefail, saw a nonzero
exit on the same text and reported the step wired. The finding
is the `| cat` instance. The mechanism is "the shell is assumed, not derived".

**Fix.** runnerShell at test/authored-bytes.test.ts:228 derives the shell from
the step's `shell:`, else the job's `defaults.run.shell`, else the workflow's.
Unset maps to `bash -e`, and `bash` maps to
`bash --noprofile --norc -eo pipefail`. Any other value throws, and so does a
`runs-on` that is not `ubuntu-*`. executeStep at
