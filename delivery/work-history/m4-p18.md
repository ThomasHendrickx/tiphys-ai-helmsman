## 2. The mechanism, and the one flag the whole phase turns on

Criterion 2 asks for the durable set to be DATA rather than a list inside the
command. The question "is this path ephemeral" is therefore put to git, against
the fleet `.gitignore` that `tiphys init` wrote, at src/commands/sync.ts:186:

```
git check-ignore --no-index -v -z --stdin
```

`--no-index` is the load-bearing word and it is worth stating why, because the
obvious form of this command is the wrong one. Without it, `git check-ignore`
answers "would git ignore this path", and git never ignores a TRACKED file
whatever `.gitignore` says. So the obvious form answers "not ignored" for
exactly the file this command exists to exclude. Measured, one path, one
repository, one variable changed (witness/captures/m4-p18-git-contracts.txt,
sections 2 and 3):

| probe, on a TRACKED `state/orchestrator.lock` | exit | output |
|---|---|---|
| `git check-ignore -v -z --stdin` | 1 | empty |
| `git check-ignore --no-index -v -z --stdin` | 0 | `.gitignore` 1 `state/` |

That is also why the dangerous state throughout this phase is a TRACKED file
under an ignored prefix rather than an untracked one. An untracked ignored file
is excluded by git itself and no command has to be careful. A tracked one is
picked up by every `git add -A` for ever, and criterion 2's own fixture is how
one comes about: the fourth prefix arrives AFTER the file.

The exit codes are three and not two. 0 means at least one path matched, 1 means
none did, 128 means git could not answer; src/commands/sync.ts:182 refuses on
128 and names the code, because folding it into "nothing is ephemeral" is how a
command reports a clean sync while committing a lease.

## 3. Design decisions

- **D1. `sync` takes no `--message`.** Criterion 6 asks for a commit message
  carrying no AI model or tool name. A message an operator supplies is a message
  this command has no control over, so the message is composed here, at
  src/commands/sync.ts:63, from a template and a COUNT. It carries no paths on
  purpose: a fleet's decision records are named after what they decide, which
  routinely includes the harness or the model a decision is about, and a message
  composed from paths inherits whatever they are named.
- **D2. A staged ephemeral path is a refusal, not a silent skip.** `git commit`
  commits the INDEX, not the pathspec it was handed, so proceeding would commit
  it. Unstaging on the operator's behalf is a change to work this command did
  not create, which is the shape CLAUDE.md standing warning 8 records for
  `git checkout --`. The refusal names the path and the `.gitignore` rule, and
  test/sync.test.ts:357 asserts the index is byte-for-byte as the operator left
  it afterwards.
- **D3. The remote is established BEFORE the commit.** The discipline is commit
  AND push. A command that committed and then found nowhere to push would have
  done the half AGENTS.md says gets dropped and reported the half that does not.
  src/commands/sync.ts:243 refuses first.
- **D4. A failed push is a nonzero exit carrying git's own first stderr line**
  (src/commands/sync.ts:358), never a warning beside a success. The relayed line
  is git's, not one composed here, which is T-003's rule and CLAUDE.md standing
  warning 10.
- **D5. The durable status document lives at `status/current.json`**, a new
  tracked directory, rather than inside an existing durable one. `charter/`,
  `decisions/` and `tasks/` each have a meaning that a status pointer is not
  part of, and `tiphys resume` rebuilds only the ephemeral three, so a durable
  directory has to come across in the clone. It does: init writes a tracked
  `.gitkeep` into it and test/status.test.ts:323 clones a fleet home and
  asserts the directory arrives while `state/` does not.
- **D6. C-1 is untouched by the split and that is the point.** `readCurrent` at
  src/status.ts:160 opens one whole document and has no code path that reaches
  the stream. Moving the document changes WHERE it lives and nothing about how
  current state is read, which is why the existing C-1 witness needed
  re-pointing rather than rewriting.

## 7. What this phase did NOT cover

Written before the gate evidence because a reviewer's first check is this
section.

- **A non-fast-forward push.** Every test pushes to a bare remote this phase
  created, or to a URL that does not exist. A remote that has moved ahead
  produces a different git refusal, and no test here exercises it. The command
  relays whatever git says, so the arm is reached, but its wording is not
  witnessed.
- **A push over a network transport.** The captured push failure is a
  filesystem path. An HTTPS remote refusing on credentials produces a different
  first line and is not in the capture.
- **A detached HEAD.** `git push <remote> HEAD` from a detached HEAD does not
  resolve to a branch. A fleet home is not expected to sit at a detached HEAD,
  but nothing in this command checks it and no test covers it.
- **The `git add` and `git commit` failure arms.** src/commands/sync.ts:319 and
  src/commands/sync.ts:344 are defensive. With the durable set derived as it is,
  no path handed to `git add` matches an ignore rule, so an unrelated git
  failure (an index lock, a permission error) is the kind of thing that would
  reach them. I did not find a way to stage one without mutating the source.
  Open question, not a claim of unreachability: the arms are unwitnessed.
- **Concurrency.** Two `tiphys sync` runs against one fleet home at the same
  time are not tested and no locking was added. The lease at
  `state/orchestrator.lock` is not consulted by this command.
- **`.gitignore` negation patterns.** The derivation delegates parsing to git,
  so a `!pattern` line is honoured by construction rather than by a test, and
  no fixture here carries one.
- **The ephemeral question outside `src/` and `bin/`.** Stated in section 2a
  with the grep that bounds it.
- **M4-P6's criterion 7 names the pre-split path.** delivery/plan/kernel-plan-m4.md:968
  requires `state/status/current.json` to reflect the last state. That phase has
  not landed; after this one its criterion names a path the kernel no longer
  writes. I did not edit the plan, which is not on this phase's list. It is
  raised to the orchestrator in the phase report.
- **A fleet home whose `.gitignore` was deleted.** `git check-ignore` then
  matches nothing and every changed path is treated as durable. No test covers
  it, and the command does not check the file's presence.
